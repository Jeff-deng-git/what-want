## 0. 关键发现（差异性结论）

1. **截图实为 ch02 step-1，不是 ch01**：截图标题"区分自检清单"对应 ch02 step-1「内外标准对照」（草案根因部分已明确）。草案主体按 ch02 写，对 ch01 step-1「误区自检清单」**未涉及**。这篇修订稿**同时覆盖 ch01 + ch02**——ch01 是 5 固定项勾选结构，ch02 是开放列表结构，两种 pattern 都要支持。

2. **草案 sql 治本 Bug A 有死锁风险**：`MAX(created_at)` 在多行同值时会漏行（GROUP BY 拿到的 max_at 可能对应不只一行），导致依然返回重复。正确写法用 `ROW_NUMBER()` 或 `DISTINCT (name, provider)` 取最新。

3. **草案 input_schema 类型覆盖不全**：草案只列了 `text / list_of_items / select / radio` 4 种，**没覆盖 ch01 的「5 固定项 + 多字段」结构**。需新增 `checklist` 类型。

4. **草案锁角色用 `disabled` 下拉 = 视觉噪音**：默认就是只读项，没必要保留下拉。修订为「静态标签 + 锁图标」。

5. **草案 LLM 序列化格式可读性差**：`text="..." drive=external` 是程序视角，不是 LLM 视角。修订为自然语言「外部驱动：加班做项目」。

## 3. input_schema 字段定义（修订）

### 3.1 类型表

| type              | 适用场景                | 渲染形态                            |
|-------------------|------------------------|------------------------------------|
| `text`            | 单段长文本              | textarea                            |
| `list_of_items`   | 开放列表 + 每项结构化    | 嵌入式 list + [+] 加行              |
| `checklist`       | 固定 N 项 + 每项多字段  | 5 卡片竖排（ch01 用）               |
| `select`          | 单选（顶层）            | 下拉                                |
| `radio`           | 单选（少量 options）    | radio 按钮组                        |

### 3.2 通用字段属性

- `name`（必需）：字段名，用作 JSON key
- `type`（必需）：见 3.1
- `label`：UI 显示名（缺省用 name）
- `required`：bool，默认 false
- `placeholder`：hint 文本
- `default`：默认值
- `show_when`：触发条件（"checked" / "always" / 表达式）

### 3.3 提交格式

```json
{
  "user_answers": {
    "misconceptions": {
      "checked_ids": ["1", "3"],
      "external_voices": {
        "1": "我爸总说选错行一辈子完了",
        "3": "我觉得不确定喜欢啥就什么都不敢试"
      }
    },
    "drive_items": [
      { "text": "加班做项目", "drive": "external" },
      { "text": "学新东西", "drive": "internal" }
    ],
    "notes": "周末想写点东西"
  }
}
```

- 旧 `user_answers: ["string"]` 格式保留，新代码读到时 fallback 成 `{notes: "string"}`，避免破坏 93 个旧测试

  - **安全动作（吸收方案 C）**：点击后先弹确认框，列出将要禁用的角色 name + provider + 当前 prompt 预览，用户勾选确认后才执行；不静默批量禁用

## 6. 后端治本修复（修订）

### 6.1 Bug A：`list_roles` 去重 SQL 修正

**草案 SQL 死锁**：当多行有相同 `MAX(created_at)` 时，JOIN 会匹配多行，依然返回重复。

**修订**：用 `ROW_NUMBER()` 取每组最新：

```sql
SELECT * FROM (
  SELECT r.*, ROW_NUMBER() OVER (
    PARTITION BY r.name, r.provider
    ORDER BY r.created_at DESC, r.id DESC
  ) AS rn
  FROM llm_roles r
  {where_enabled}
) t
WHERE rn = 1
ORDER BY t.created_at
```

> ⚠️ 注意：本项目数据库为 **SQLite**，`DISTINCT ON` 是 PostgreSQL 专有语法，在 SQLite 下会直接报错。请以**上方 ROW_NUMBER() 写法为准**，勿用 DISTINCT ON。

### 6.2 Bug B：UNIQUE 约束

草案已写对，加 `CREATE UNIQUE INDEX ... WHERE enabled = 1`。
**注意**：加约束前必须先手动 `UPDATE enabled=0 WHERE id IN (重复行的 id)`。

### 6.3 创建立即检查

草案 5.2 已写对，前端 `newRole()` 弹窗收到 409 时显示「已存在，去管理页编辑」。
