## Q1. ch03 output_fields 是否需要 `intersection`？
- 现状：`chapter_config_ch03.json` exercises[0].output_fields = `[likes, talents, importance, intersection]`，四个 editable_list。
- 交接文档 §7.3：用户分别输入三类各 3-5 项；LLM 不判对错而是辅助纠正混淆、引导拆解、取交集。
- 疑问：当前配置把 `intersection` 与 likes/talents/importance 并列，意味着前端会让用户**手动填**第四组 chip，与"LLM 取交集"语义不符。
- 选项：
  - A：删除 `intersection`，仅保留 likes / talents / importance。LLM 输出 `intersection` 字段落 profile，前端只展示 LLM 结果。
  - B：保留 `intersection` 作为用户可微调的候选交集。前端把 LLM 输出填进 chip，用户可手动增删。
  - C：保留但加注释"用户可调整"，前端明确标注 LLM 取的初始值。

**A(设计侧)：** 选 **A 方向（但措辞修正 — 不应删除 intersection 字段）**。依据：handoff §7.3 行 273–277 + §7.9 行 344
- 交接文档 §7.3 行 274 明确 `output_fields = likes, talents, importance, intersection` 四个；**§7.9 行 344 防跑偏："❌ 不要新增/删 output 字段名"**——字段不能少。
- §7.3 行 273 user_action：「LLM 不判对错，而是辅助纠正混淆、引导拆解、取交集」——**交集由 LLM 取**，不是用户手填。
- §7.3 行 277 验收：「intersection 汇总句生成」——LLM 生成汇总句。
- config 当前 `lockable: true` 误导前端渲染为可手填 chip；正确做法：
  1. **保留字段名 intersection**（不删，与 handoff 一致）
  2. `lockable: true` 改为 `lockable: false`（用户不可锁，因 LLM 持续更新；锁住会导致后续 LLM 重算失败）
  3. 前端**不**渲染为可填 chip，而是「LLM 输出展示卡」（只读）；用户确需手动覆盖时，走章末"备注"机制，不直接编辑 intersection
  4. 截图实情：ch03 截图只渲染了一个 textarea（应是让用户填 likes/talents/importance 三类的入口），**没有 intersection 的独立 UI**——这是 UI 没做齐，不是字段冗余
- **B/C 选项（用户手填或可调整 intersection）与 handoff 语义不符**；A 方向对但措辞应为"保留字段、改语义为 LLM-output-only"。

## Q4. ch07 markdown 1.4MB 导致页面卡死，如何处理？
- 现状：开发侧在 `renderMarkdown` 加 size guard（>200KB 走 `<pre>` 降级），保证页面可用，但失去富文本排版。
- 选项：
  - A：恢复富文本，但只渲染首屏 200KB 章节，其余滚动到视口附近再异步拼接。
  - B：把 ch07 md 切分成多个小 md（按二级标题切），前端分章节 fetch。
  - C：维持 `<pre>` 降级，UI 不再美化但保证可用。

**A(设计侧)：** 选 **A 优化版（保持物理单文件 + 前端按二级标题逻辑切片 + 视口附近懒加载）**。依据：handoff §7.9 行 343 + config `md_source` 字段语义
- handoff 与 config 未对单章 markdown 大小做限制，但**全书每章是单 md 文件**（config 字段 `md_source` 指向单文件路径，handoff 全文以"单章单文件"为前提）。
- 物理切分（B 选项「多个小 md」）会破坏单章单文件结构——切分应是**逻辑切片**而非物理切分；B 选项把"按二级标题切"理解成物理切分，与原设计略冲突。
- 维持 `<pre>` 降级（C 选项）牺牲 UX；**当前 size guard 是 200KB、ch07 是 1.4MB**——`<pre>` 是常态，无法满足交付标准。
- A 选项（保留富文本 + 视口附近懒加载）与原设计兼容，UX 最佳。

**具体实现**：
- 保持物理单文件（`chapter_md/第七章-...md` 不切分）。
- 前端 markdown parser 解析出所有二级标题（`## ...`），按二级标题切片。
- 初始只渲染首屏二级标题块（≈200KB 内）；用户滚动到视口附近时异步拼接下一块。
- LLM 注入侧：§7.9 行 343 已约束按 `md[:md_cap]` 切片，前端可复用同一 cap 边界（首屏 ≈ 200KB）。
- 若某二级标题段自身过长（> 200KB），可对该段再做三级切片（`### ...`）。

**备选**：若工程上物理切分更省事，**B 也可**，但需明确：
- 切分标准 = 二级标题（不是任意字符切分）。
- 保留原单文件作为拼接源（避免单章语义丢失；前端拼接时不破坏目录结构）。
- 新切的小文件命名建议 `chapter_md/第七章-...-{序号}.md`，并在 `chapter_config` 里加 `md_chunks` 数组指向各分片。
