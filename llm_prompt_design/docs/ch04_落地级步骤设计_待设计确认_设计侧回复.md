## 一、逐条确认（Q1–Q8）

### Q1. 导师 `mentor_hooks.references` 最终字段 → 确认 `[importance]`
- ch03 真实产出字段为 `importance`（另有 `talents`/`likes`/`intersection`），**无 `formula`**；`formula` 仅是概念公式（喜欢×擅长×重要），不是落库键。
- ch04 导师引用 ch3 的 `importance` 正确。config 已是 `["importance"]`。
- 需同步：① `mentor_design_spec.md` 钩子表 `[formula]`→`[importance]`（**已改**）；② active DB reseed；③ `test_context_integrity.py` 期望值若硬编码 `formula` 须同步。
- `formula` 不再作为任何章节 profile 键；spec 第 86、221 行的 `formula` 属陈旧残留，建议统一重构时清理（非阻塞）。

### Q2. 导师对话加载哪些 ch04 上下文 → 确认「分层上下文」
- 采用开发侧建议分层：① 压缩 profile（`importance`/`values`/`ranked`/`work_purpose` 等）；② 本章**已提交** step 的筛选后摘要（step-1 五问+`top_values`、step-2 `groups`、step-3 `conversions`、step-4 `ranked`、step-5 经历+`work_purpose`+`experience_map`）；③ 最近 8–12 轮对话；④ 统一 token 上限，优先截断历史再缩减 step 上下文。
- **未提交 step 不进入导师上下文**（与「提交即锁定」一致）。导师读「筛选后摘要」，非八章原始 JSON 全量注入。

### Q3. step-2「≥15 关键词」如何进入 LLM → 确认「补充关键词走 `supplemental_keywords`」
- 采用开发侧建议新字段：step-2 新增 `input_schema.supplemental_keywords`（`list_of_items`，非必填；**已写入 config**）。
- 计数：`N/15` = `step-1.top_values` ∪ `supplemental_keywords` 去重后数量。
- 「100 例清单」引用、自由输入均只写 `supplemental_keywords`；重生成时 LLM 同时读注入的 `top_values` 与 `supplemental_keywords`。
- UI 上对关键词池的增删以「屏幕可编辑 chip 列表 = 最终提交池」为准；锁定项经 `preserve_output.groups` 传入（见 Q4）。「100 例清单」抽屉为前端细节，由开发实现（源 `chapter_md/问题清单.md`）。

### Q4. `preserve_output` 锁定项保留规则 → 确认开发侧建议语义
- `preserve_output` 透传**当前完整编辑结果**；后端/assembler 提取 `locked=true` 项；**LLM 只返回未锁定项**；后端按原位置合并；**LLM 不得改锁定项内容与位置**。
- 锁定项**保留原位置**（值+位置均锁定）。
- 用户**删除已锁定项前须先解锁**；解锁后才可删，删后该位置重生成可填充。
- 落地文档与 mockup 须体现「锁定项位置不变」。

### Q5. step-3 `why_chain` 是否严格 5 节点 → 确认「1–5 弹性」
- `type=other` 允许 **1–5** 节点，LLM 判断收敛，**不凑 5**；`type=self` 的 `why_chain` 可为空。
- 用户可编辑/删除/补充节点；`converted_to` 对 `type=other` 应非空，确实无法转化允许 `converted_to:""` 并提示继续对话。
- 「5Why」为方法论名（最多 5 层），非硬计数。

### Q6. step-5 textarea 与 API 格式 → 确认「textarea + 按行拆分」
- UI 用**一个多行 textarea**，每段一行；前端按行拆分，每行→1 条 `experience`，提交为 `list_of_items`（min_items=10），与 config `input_schema` 对齐（**PRD-ch4 §1.7 已补显式转换契约**）。
- 不采用 10 个独立输入框，不做切换。

### Q7. `mentor_hooks.references` 作用域 → 确认「仅导师」+ 新增 `step_context`
- 采用第三种方案：`mentor_hooks.references` **只用于导师**，绝不进普通 step 的 LLM prompt。
- ch04 config 已新增顶层 `step_context: {references: []}`（与 ch03 同构），显式声明本章 step 无跨章 profile 注入，阻断 `assembler.py` 回退 `mentor_hooks.references` 的泄漏 bug（同 ch03 已修路径）。
- 开发须确保 `build_step_prompt` 只从 `step_context.references` 取 step 级注入；`mentor_hooks.references` 仅供 `chat.py` 装配导师上下文。

### Q8. 「不替用户定性」与 LLM 自动归纳的边界 → 确认「草稿→提交才生效」
- 所有 LLM 生成的结构化字段（`top_values`/`groups`/`conversions`/`ranked`/`work_purpose` 等）**先作「AI 建议 / 草稿」**，用户提交 step 后才成为正式结果入 profile。
- UI 统一标注「AI 建议」，不冒充「你的价值观 / 你的最终目的」；用户可编辑、锁定、覆盖（如 step-5 `work_purpose` 手动覆盖）。
- 导师不做最终价值判断，只映照、追问；与 ch04 各 step `user_action`「LLM 不判对错 / 不替定分组 / 不替定性」一致。
- **（2026-08-10 产品负责人已确认此 UX 口径，无需再拍板。）**
