## 2. 待设计侧确认的问题

### Q1. 30 问回答的 canonical 字段、归属和输入规则

设计侧回复中确定了“独立 scratchpad”，但目前 `chapter_config_ch06.json` 的 `input_schema` 没有声明 30 问回答字段。

当前 step 输入字段为：

- step-1：`q1`–`q5`
- step-2：`reference_talents`、`passion_seeds`

请确认以下内容：

1. 30 问回答使用什么 canonical 字段名？开发侧建议使用明确的字段名，例如 `passion_questions` 或 `question_answers`，但不自行定名。
2. 该字段归属于 step-1、step-2，还是作为本章统一 scratchpad？
3. 每条数据的 canonical 结构是什么？例如：

   ```json
   [
     {
       "question_id": 61,
       "question": "题目原文（可选）",
       "answer": "用户回答"
     }
   ]
   ```

4. 题库当前接口返回全局 `q_order`。热情题目在现有题库中属于筛选后的 30 条，但请确认持久化时使用：
   - 全局 `q_order`（当前实现预计为 61–90）；还是
   - 热情分类内的 1–30 序号；还是
   - 题目稳定 ID。
5. 是否需要同时保存题目原文，避免题库内容更新后历史回答无法回溯？
6. 30 问回答是否在点击“运行 LLM”时作为 step-1 / step-2 的 user evidence？如果是，请明确：
   - step-1 是否读取追加回答并重新生成领域级 `likes`；
   - step-2 是否读取追加回答，并与 step-1 `likes`、`reference_talents`、`passion_seeds` 一起分析；
   - 哪些字段只作为上下文，哪些字段可以进入最终 `likes`。
7. 30 问回答是否在正式提交前始终只属于草稿 scratchpad，不能进入 `learner_profile`、导师上下文或 ch07？

补充背景：现有题库回答接口 `platform/backend/app/routers/questions.py` 将回答保存到 `book_notes`，这与 ch06 step draft 不是同一个载体。请确认本章是否需要把题库回答同步写入 ch06 的 draft `user_answers`，还是只复用 `book_notes` 并在运行时读取。

### Q2. step-1 的 `saved` / `submitted` 与 step-2 级联边界

当前运行时级联读取逻辑只查询前序步骤 `status = 'submitted'` 的结果：

- `platform/backend/app/runtime/agent.py` 的 `_load_prior_outputs()`。

但设计文档中同时使用了“运行（/run）”“提交”两个概念，前端也将“运行 LLM”和“提交”拆成两个按钮。因此需要固定以下流程：

#### 需要确认的主规则

请确认是否采用开发侧建议的方案 A：

> step-1 点击“运行 LLM”只生成 `saved` 结果；用户必须继续点击“提交”，step-1 才进入 `submitted`，step-2 才能读取其 `likes`。

如果不采用方案 A，请明确方案 B：

> step-1 只要运行成功成为 `saved`，step-2 即可读取该结果，不要求先点击“提交”。

#### 还需要固定的边界行为

1. step-1 尚未 `submitted` 时，step-2 页面是否显示“请先提交第一步”的引导并禁止运行？
2. step-1 已运行但未提交时，100 例引用和 30 问回答能否继续保存为 step-2 草稿？
3. step-1 重新运行或重新提交后，已有的 step-2 `saved` / `submitted` 结果如何处理：
   - 保留旧结果并标记需要重新运行；还是
   - 自动失效/回退 step-2；还是
   - 允许继续保留，但运行 step-2 时必须使用最新 step-1 `submitted` 输出。
4. step-2 运行时是否必须同时引用：
   - 最新的 step-1 `submitted.likes`；
   - 当前 step-2 草稿中的 `reference_talents`；
   - 当前 step-2 草稿中的 `passion_seeds`；
   - 已确认的 30 问回答（如果 Q1 确认纳入）。

开发侧建议采用“submitted-only + 最新 submitted 结果”规则，原因是它能保持草稿、saved、submitted 隔离，避免未确认结果污染后续步骤；但该建议不替代设计侧拍板。
