### 3.2 `reference_strengths` 是否进入最终 `talents`

**结论：用户从「100 例清单」点「引用」= 显式采纳该项为自身长处 → 提交时并入最终 `talents`（带 `source:'100_examples'`），与 step-1 长处合并去重。**

逐项回答 dev 子问题：
1. 100 例引用项**进入**最终 `talents`（引用即采纳）。
2. 进入时**保留 `source` 字段**（`source:'100_examples'`），与自发长处（`source` 缺省）区分。
3. 即便不点击引用，该项也可作为 LLM 的参考素材被重新表达成一个与用户素材相关的长处（但那是 LLM 生成的新项，不带 `source`）。
4. **N 的计算** = 当前编辑中的 `talents` 列表长度 = step-1 初版 + 用户手动新增 + 100 例引用项（三者合并去重后的实时列表）。已在 config 的 `reference_strengths` label 与 PRD §2.2 计数说明中写明。
5. **去重**：精确字符串去重由 runtime 在存储时做；语义相近项合并由 LLM 在生成时做（prompt 已要求「汇总去重」）。

> 关于专家评审记录 P1-7 的「不混入 talents」：**该口径已被本次更新正式替代**——`reference_strengths` 是抽屉瞬时输入（编辑态独立展示，**不与 `talents` 混排**），但用户点「引用」时即并入编辑中的 `talents`（带 `source:'100_examples'`），**提交时与 step-1 长处合并去重、一并落库**（非独立持久字段）。详见落地文档 §10 P1-7 修订版 + PRD-ch5 §3.1.2 user prompt 模板修订版。

### 3.3 `talents` 的 canonical 数据结构

**确认采用统一 schema，且已写入 config（非仅 prompt 文本）：**

```json
{ "text": "具体长处", "rating": "◎|〇|△|空字符串", "locked": false, "source": "100_examples(可选)" }
```

逐项回答：
- step-1 **也输出对象数组**（rating 初始为空、`locked:false`），不再输出 `string[]`。config 两处 `output_fields.talents` 均挂 `item_schema`，step-1 instruction 已写明「每项形如 {text, rating:初始为空, locked:false}」。
- 进入 step-2 **无需运行时再标准化**（已经是对象数组，结构一致）。
- step-1 的 `locked` **存在**（默认 false），用于提前锁初版。
- `rating` **允许为空**（初始态）。
- profile 中最终保存的 `talents` **始终是对象数组**。
- 允许保留 `source` 等额外字段（`item_schema` 中 `source` 标记为 `optional`）。

### 3.4 「单项锁定」与「整步提交锁定」的关系

**正式状态规则（runtime 依据 `routers/steps.py` 提交态 + `preserve_output` 实现）：**

1. 提交前锁定单项 → **仅影响下一次 LLM 重生成**（该项进入 `preserve_output`，重生成时原样保留）。
2. 重生成时，**已评级但未锁定的项允许被 LLM 覆盖**（除非锁）。
3. 用户解锁后 → 允许重生成覆盖该项。
4. step `submitted` 后 → **整步不可编辑**（`edit_output` 在 `status=="submitted"` 返回 409）。
5. 修改已提交结果 → **新建 run**（「重新生成 / 换一种说法」按钮新建草稿 run，不覆盖已提交记录）。
6. 新 run 提交前，旧 `submitted` 仍是 profile 唯一有效版本；新 run `submitted` 后覆盖。
7. **锁定项必须保留原位置** → 已确认是 ch05 正式规则（运行时 `merge_preserved_output` 按原位置保留，mockup 的 `regen()` 已实现原位置保留 + 提示保留数）。

### 3.5 《使用说明书》是否允许用户编辑

**选 A：只读，只能重新运行 LLM。** 用户不能就地编辑 `user_manual` 文本。

- config `user_manual` 为 `readonly:true`，落地文档 §6 已声明。
- **已修 PRD §2.2** 原「用户可微调文本」→「只读，LLM 生成；如需调整只能重新运行 LLM」。
- 编辑结果不进 profile（仅 `talents` 进 profile）；不参与导师上下文；重生成时 `user_manual` 由 LLM 重新生成（不被 `preserve_output` 锁定）。

### 3.6 ch05 导师读取的上下文边界

**遵守全局硬规则：导师严格只读 `submitted` 输出，绝不读草稿 / 未提交 LLM 结果。**

逐项回答：
1. 导师只读 submitted → 是（已写入落地文档 §贯穿 约束）。
2. 用户在 step-2 运行 LLM 但未提交时，导师**能看到 step-1 已提交输出**（step-1 已 submitted），看不到 step-2 未提交结果。
3. 导师进入 step-2 时，**注入本章全部已 submitted 步骤**（当前 runtime `chat.py` 仅注入一个 step，属开发待办，需扩展到本章全部 submitted）。
4. `work_purpose` **仅作导师钩子**（`mentor_hooks.references`），绝不进入 step-1/step-2 普通分析 Prompt（由 `step_context`/`ui_context` 显式声明，当前均为 `[]` 已保证）。
