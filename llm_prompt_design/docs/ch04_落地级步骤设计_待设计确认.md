### Q3. step-2 的“至少 15 个关键词”如何进入 LLM？

#### 当前契约问题

设计要求 step-2：

- 汇总至少 15 个关键词；
- 用户可以增删关键词；
- 用户可以从“100 例清单”引用关键词；
- 用户可以让 LLM 重新分组。

但当前 config 中 step-2 没有 `input_schema`，只有：

```json
{
  "references": [
    {"from_exercise": "step-1", "fields": ["top_values"]}
  ]
}
```

step-1 只承诺输出 5–10 个 `top_values`。因此用户补充的关键词必须有明确的提交路径，否则 LLM 仍然只能看到 step-1 的 5–10 个词。

#### 请设计侧确认用户补充数据的权威位置

请明确以下方案之一：

- [ ] 用户补充关键词写入 step-2 的 `user_answers`，并由 prompt 显式读取；
- [ ] 用户补充关键词直接写入 step-2 的 `parsed_output.groups`，重新生成时作为现有输出处理；
- [ ] 用户补充关键词通过 `preserve_output` 传入；
- [ ] 另设字段（请给出字段名、类型、保存时机和 prompt 读取方式）。

#### 建议的数据契约

如果设计侧没有更优方案，开发侧建议新增 step-2 输入字段：

```json
{
  "supplemental_keywords": ["自由", "创造", "表达"]
}
```

并明确：

- 计数 `N/15` = `step-1.top_values` + `supplemental_keywords` 去重后的数量；
- 100 例引用只写入 `supplemental_keywords`；
- 重新生成时，LLM 同时读取原始 step-1 输出和补充关键词；
- 用户已编辑/锁定的 group 仍通过 `preserve_output.groups` 传入。

### Q4. `preserve_output` 的锁定项保留规则

#### 当前运行时缺口

当前 `RunIn` 已定义 `preserve_output`，但实际调用链没有透传：

- `steps.py:84-87` 定义请求字段；
- `steps.py:311-312` 调用 `agent_run_step` 时只传 `chapter_id / step_id / user_answers`；
- `agent.py:199-238` 的 `run_step` 没有 `preserve_output` 参数；
- `assembler.py` 的 `build_step_prompt` 也没有接收该参数。

因此设计中“重新生成时保留锁定项”当前没有真实实现。

#### 需要设计侧锁定的语义

请明确：

1. `groups` 的 locked 项是否必须保留原位置？
2. `ranked` 的 locked 项是否必须保留原位置？
3. locked 项是否允许用户修改后再次锁定？
4. LLM 输出是：
   - 返回完整数组（包含锁定和未锁定项）；还是
   - 只返回未锁定项，由后端合并锁定项；
5. 用户删除已锁定项是否允许？删除后重新生成是否允许该位置被填充？

#### 开发侧建议

建议采用：

- `preserve_output` 传递完整的当前编辑结果；
- 后端/assembler 明确提取其中 `locked=true` 的项；
- LLM 返回未锁定项；
- 后端按原位置合并锁定项和新生成项；
- LLM 不得修改 locked 项的内容和位置。

如果设计侧只要求“值保留、不保证位置”，请明确写入落地文档和 mockup，避免 UI 与后端不一致。
