## §0 概要

ch08 不是「练习/步骤流」章，而是**全书可视化流程图**——一张对整本书的总结性**决策导航页**。

- **形态**：独立页型 `page_type: "flowchart"`（schema 已扩展支持），类问卷：按阶段展示决策点，用户对每个问题选「是/否/找到了/没找到」等分支，并在每个决策点**写备注**（持久化、后续可查看）。
- **跳转**：选「否/找不到」时**真实跳转**到对应章（ch04 价值观 / ch05 长处 / ch06 喜欢 / ch07 组合筛选）；选内部分支时在同一流程图内跳到下一个决策点。
- **无 LLM 步骤、无 profile 写入**：流程图是纯导航 + 备注，不调用 step 流程、不落 `learner_profile` 任何键。
- 色彩浴、海胆、成功定义按原书定位为**比喻与哲学阐述**，不是结构化练习步骤（详见 §7 设计判断）。

---

## §1 目标用户与角色

- **目标用户**：读完全书或读到一半、卡在「不知道下一步该做什么」的读者。书里原话：「当你不知道下一步该做什么时，请翻到这页，重新梳理方向。」
- **mentor（导师）**：ch08 页面右侧仍可开「与导师对话」Tab。`mentor_hooks.references` = 全书旅程上下文（`values` / `work_purpose` / `talents` / `likes` / `ideal_works`），让导师能基于用户已写下的备注与全章产出给方向建议（详见 §7 判断 4，此为设计侧建议、可调整）。

---

## §2 一步 vs 多步

- **不是步骤流**：ch08 无 `exercises`、无 `step_id`、无 submit 状态机。它是一个**单页流程图**，前端按 config `flowchart.stages[].decision_points[]` 渲染决策点与分支。
- **渲染单元**：每个 `decision_point` = 一张「问题卡」：问题文案 + N 个分支按钮（label）+ 一个可选备注输入框（comment_enabled=true）。用户选分支后，按 `next` 或 `jump` 进入下一节点。
- 与 ch01–ch07 的 `exercises` 渲染器**完全解耦**，需新增 `flowchart` 页型渲染器（前端）与 config 加载分支（后端 `load_chapter_config` 按 `page_type` 分发）。

## §3 流程图（决策点树，源自原书 md 末尾【全书可视化流程图文字说明】）

```
阶段一 · 探索价值观（dp-1 → dp-2）
  dp-1 是否明确自己为何而活？
    是 / 找到了价值观          → dp-2
    否                        → 跳 ch04 价值观练习
    找不到价值观              → 跳 ch04 value_questions（30问）
    还是没找到                → 跳 ch04 value_questions（带⭐=全部30问）→ 明确工作目的后 → dp-2
  dp-2 是否明确工作目的？
    是                        → dp-3
    否                        → 跳 ch04（明确工作目的）

阶段二 · 探索长处（dp-3）
  dp-3 是否有能取得成果的长处？
    是 / 找到了 / 找到了长处   → dp-4
    否                        → 跳 ch05 长处练习
    没找到                    → 跳 ch05 talent_questions（30问）

阶段三 · 探索兴趣（dp-4）
  dp-4 有没有感兴趣或有热情的领域？
    否                        → 跳 ch06 喜欢练习
    没找到                    → 提示「喜欢的事终究只是实现工作目的的手段…」→ 回 dp-4 重新判断
    是                        → 跳 ch07（组合喜欢×擅长，假设想做的事）

阶段四 · 提炼目标与落实手段（dp-refine → dp-5）
  dp-refine 通过工作目的提炼出想做的事？
    去提炼                    → 跳 ch07（筛选定稿）
    提炼成功                  → dp-5
  dp-5 是否找到实现真正想做的事的手段？
    找到了 / 找到了（收集后）  → end
    没找到                    → 提示「通过书、网络、研讨会等收集信息」→ end

终点 end：辛苦了！全身心投入到实现真正想做的事情中去吧！
```

**真实跳转目标映射（config `jump` 字段，已对齐各章 canonical config 键名）**：

| 决策点分支 | 目标章 | question_key | 说明 |
|---|---|---|---|
| dp-1 否 / 找不到 | ch04 | — / `value_questions` | 价值观练习 / 30问 |
| dp-2 否 | ch04 | — | 明确工作目的 |
| dp-3 否 / 没找到 | ch05 | — / `talent_questions` | 长处练习 / 30问 |
| dp-4 否 | ch06 | — | 喜欢练习 |
| dp-4 没找到 | ch06 | `passion_questions` | 30问 |
| dp-4 是 | ch07 | — | 组合喜欢×擅长（ch07 step-1） |
| dp-refine 去提炼 | ch07 | — | 用工作目的筛选定稿（ch07 step-2） |

> **「带⭐的问题」映射**：系统当前无 starred 子集（问题清单.md 全文件 ⭐=0，后端无 star 路由），按用户定义「全部 30 问即⭐」，故 `jump.question_key` 指向该章**全部** 30 问（value_questions / talent_questions / passion_questions）。构建「仅答带⭐子集」为平台后续特性（见 §9 开放点）。

## §4 依赖（软提示，无硬门禁）

- **进入不锁**：ch08 是全书总结页，按书意应在任意阶段可进。采用**软提示**——进入时后端读取 ch04–ch07 的 profile 完成态（`values`/`work_purpose`/`talents`/`likes`/`ideal_works` 是否非空且对应 step-run `stale=0`），若某章未完成，页面顶部显示一条引导：「建议先完成：ch04 价值观 / ch05 长处 / ch06 喜欢 / ch07 想做的事」，每项带「前往」按钮。
- **不做硬门禁**：与 ch04–ch07 的进入门禁不同，ch08 不阻断访问——用户可以先翻流程图、再被引导去补做某章。

---

## §5 锁定类型

- ch08 无 `lockable` / `readonly` 字段（非 exercise 页）。
- 用户备注为自由文本，存 `flowchart_state`，无锁机制；用户可随时改、随时删。

---

## §6 stale（无内部级联，仅上游 stale 软提示）

- **无内部 stale 级联**：ch08 不写 `learner_profile`、不持有任何 profile 键，故不存在「重提交上游→下游 stale」的链条。它在 `ch04_stale隔离_开发侧待办.md` §8.2 中被归类为「无内部 stale 级联」。
- **进入时读上游完成态**：软提示依赖 ch04–ch07 的 profile 字段**且须带 `stale=0` 校验**（复用既有 12 个 stale 过滤入口的判定逻辑）。若某上游章存在 `stale=1` 的已提交 run，则该章在软提示中标注「数据可能已过期，建议重跑」。
- **真实跳转到上游章后**：由目标章自身的门禁/stale 机制接管，ch08 不重复处理。

## §7 设计判断（与旧稿 / 历史口径的差异处理）

1. **为什么是「流程图页」而非「练习章」**：原书 ch08 唯一结构化产物是末尾的「全书可视化流程图」决策导航；色彩浴/海胆/成功定义均为**比喻与哲学阐述**（书中色彩浴是"信息自然映入眼帘"的心智隐喻，海胆是作者亲身故事，成功定义是论述），没有"每天记录/写经历"的练习步骤。故 ch08 收敛为 1 个独立流程图页，忠于原书、不过度工程化。
2. **为什么「真实跳转」而非站内引用卡**：用户在流程图的「否/找不到」分支本就要去对应章做练习，真实跳转（离开 ch08 进 ch04–ch07）最贴合书意，也避免"引用卡"造成的二次点击。返回 ch08 时按 `flowchart_state` 恢复到离开前的决策点。
3. **为什么 `flowchart_state` 独立表而非塞进 profile**：备注与路径进度是 ch08 专属的导航态，与档案字段语义无关；独立表与 compaction 白名单完全解耦，不污染 `learner_profile`，零迁移风险。
4. **mentor_hooks 引用全书上下文（设计侧建议，可调整）**：ch08 无 step 注入需求，故 `references` 仅用于**导师对话上下文**（让导师看到用户全章旅程以给方向建议），不进入任何 step prompt。若产品侧认为 ch08 不需 mentor 上下文，可清空 `references`。此为设计判断，开发侧实施前请用户确认。
5. **DP4 内部回环的简化**：原书 dp-4「组合成功 / 无法组合→回 ch06 微调」的子循环，落在 ch07 组合练习（step-1/step-2）内部与返回 ch08 后的再判断中，本流程图仅以「是→跳 ch07」表达，不单独建模子状态机。

## §8 数据复用与持久化

### 8.1 新增表 `flowchart_state`（与 profile 解耦）

```sql
CREATE TABLE flowchart_state (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id       TEXT NOT NULL DEFAULT 'local',
  chapter_id    TEXT NOT NULL DEFAULT 'ch08',
  decision_point_id TEXT NOT NULL,
  selected_branch TEXT,            -- 用户选中的 branch label
  comment_text  TEXT,              -- 用户备注
  updated_at    TEXT DEFAULT (datetime('now')),
  UNIQUE(user_id, chapter_id, decision_point_id)
);
```

- 每个决策点一行；重访时按 `(user_id, decision_point_id)` 恢复备注与上次选择。
- **当前节点推导**：第一个 `selected_branch` 为空的决策点，或上次选择的 `next` 目标；跳转离开后再返回时，恢复到离开前的决策点。
- **零 profile 写入**：不调用 `compact_profile`、不写 `learner_profile` 任何键；不进 `compaction.py` 白名单，无 DRIFT 风险。

### 8.2 读上游（仅用于软提示）

- 进入 ch08 时读 ch04–ch07 的 profile 字段（`values`/`work_purpose`/`talents`/`likes`/`ideal_works`），并校验其来源 step-run `stale=0`，用于顶部软提示与「数据可能已过期」标注。
