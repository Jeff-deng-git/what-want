## 1. 背景与两个已拍板决策（设计侧的闭环）

### 1.1 背景

平台不是「8 个独立章节 + 2 个写死的 LLM 调用」，而是一套**以用户认知进展为主线的统一系统**：

```
用户自评产出（8 章 exercises）
   ↓ 落库 step_runs（原始）
learner_profiles（压缩档案 ≤800 tok，跨章连续）
   ↓ assembler：compact + select，≤3k token 护栏
统一 Agent 运行时（agent_type = step / mentor / summary，配置驱动）
```

刘老师（mentor）与章节摘要（summary）不是某章功能，而是**贯穿全书的常驻能力**，与 8 章练习共享同一份 `learner_profiles`。

### 1.2 决策 A —— 章末桥接卡 UI 形态（Q1 闭环）

- **选定形态 B（回顾卡）**：默认展示、不强制对话，用户可一键「和刘老师聊聊」。
- **Ardot 当前不可用**（MCP 适配器 `NO_ADAPTER`），因此本卡**不通过 Ardot 出高保真稿**，改以本文 §8 的**组件规范**作为前端实现的唯一依据；Ardot 恢复后可视情况补渲染稿（非阻塞）。
- **结论**：前端现在就按 §8 实现组件（属工程里程碑 M5）。

### 1.3 决策 B —— 重构真实范围（Q2 闭环）

- **范围 = 全平台重构**：当前已实现并上线的 ch1–ch4 全部需按新配置重构一致；ch5–ch8 已有配置需对齐实现。
- **复用优先**（不影响性能前提下）：保留既有 FastAPI 框架、DB 基础、`index.html` 三栏外壳、`chapter_md` 八章正文、seed 脚本机制、`SPEC.md` 步骤运行器模式。
- **仅重写"LLM 调用层"为配置驱动**，并把八章配置(`chapter_config_chNN.json`)真正落地为运行时数据。具体复用/重写清单见 §4。

### 1.4 架构决策与评审结论（权威，已落进 schema / config / SPEC）

> 本节把后续所有"拍板 / 评审"结论内联，**开发 Agent 只需读本节即可避免跑偏**；完整理由见 `docs/ADR-001-exercises-schema.md` 与 `docs/重构plan_设计侧回复.md`（非必须读）。

**七项已拍板决策（覆盖架构师原 7 问 + 另一开发 Agent 的 review）：**

1. ★ 运行时契约 = **Option B（exercises 原生）**：重写 `step_runner` 走 `build_step_prompt`，**彻底去掉 jinja2**（legacy `steps[].llm_op.prompt_template` 作废）。
2. ★ **跨步引用（章节内级联）= `exercises[].references: [{from_exercise, fields}]`**：`build_step_prompt` 从**同章已 submitted 的前序 `step_runs.parsed_output`** 注入所需字段。
3. ★ **`output_fields` 类型化（oneOf）**：每个字段是对象 `{name, type, readonly?, lockable?}`，`type ∈ {markdown,text,editable_list,list,number,select,json,table}`；**向后兼容字符串写法**（schema 校验已通过）。
4. chapter_id 统一 `ch01..ch08`；一次性迁移 legacy `04-important → ch04` 后清 `CH_ID_ALIAS`。
5. user_id 常量 `DEFAULT_USER_ID = "local"`（前端不改；profile 表主键保留）。
6. 前端托管 = 后端 `main.py` `StaticFiles` 挂 `frontend/index.html` 到 `:8011/`，API 改相对 `/api`（消除 `localhost:8011` 硬编码）。
7. `conversation_summaries` = M1 建表、实现延迟到 M5 之后（增强项）。

**🔴 评审纠错（务必记牢，别照另一 Agent 的错误方案做）：**
- 另一 Agent 的 review（`重构plan_待设计拍板.md` Q2）称"跨步引用由按 `output_fields` 拉 `learner_profile` 实现"——**这是错的**。ch4 的 `groups`/`conversions` 是**步骤级中间产物，不进 `learner_profile`**；从 profile 拉不到 → 级联断裂。正确做法：章节**内**级联用 `exercises[].references` 从**前序 `step_runs`** 注入（见 §7.0）；跨**章**的 `mentor_hooks.references` 才读 `learner_profile`（这是两个不同机制，见 §7.0 区分）。
- 该 review 文档的 **M1–M6 里程碑可复用**，但 **Q2 机制须按本文替换**；其余 Q1 / Q3 / Q4 已被上述决策覆盖（Q3 = 新增 `agent_configs` 表，见 §4/§6.1）。

**其他评审补充点（已纳入本文各处）：** `user_id=local`、前端 `:8011` 托管、端口混乱（真实端口 8011 非 3011）、profile 字段边界、conversation_summaries 延迟实现。

## 3. 全局架构（实施必须遵循）

### 3.1 三层架构 + 统一运行时

| 层 | 职责 | 量级 |
|----|------|------|
| 系统层（恒定） | 角色人设（刘老师 / 摘要编辑 / 各章教练） | 小 ~400 tok |
| 上下文层（策展） | learner_profiles（压缩）+ 本章 MD 切片 + mentor_hooks 选出的前序字段；mentor_hooks.references 只决定优先字段，不得在为空时抑制完整 compact profile | 中 |
| 任务层（每章） | chapter_config.exercises（step 模式）/ mentor_hooks（mentor 模式） | 中 |

**三种调用统一经 `app/runtime/agent.py` 分派**（不再各自硬编码）：

| agent_type | 触发 | 配置源 | 输入 | 输出落点 |
|------------|------|--------|------|---------|
| `step` | 用户提交某章练习 | `chapter_config_chNN.json` 的 exercises | 用户答案 + 本章 MD 切片 + 声明的前序 submitted 输出 | exercise.output_fields → step_runs + learner_profile；章节内中间产物只留在 step_runs |
| `mentor` | 用户点「问刘老师」(opt-in) | `mentor_config.json` + 本章 `mentor_hooks` | learner_profile + 钩子 + 本章 MD + 滑动历史 | 对话（仅历史，不落档案） |
| `summary` | 进章 / 手动 regenerate | `summary_config.json` | 本章 MD[:12000] +（可选）profile 增强 | 摘要 tab `{summary, core_concepts[], key_process[]}` |

### 3.2 关键护栏（见 §9 红线）

- 装配后每轮 prompt **≤3k token**；超载先截历史，再退化为「仅档案 + 钩子」。**绝不全量注入八章原始 step_runs**。
- 配置真相在 **DB**（`llm_roles` / `chapter_configs` / `learner_profiles`）。`config/*.json` 仅作 **seed 源**，运行时由 `config_loader` 读 DB，**不读 JSON 文件**。
- mentor 必含 profile；summary 可选 profile 增强。

## 6. 数据层改造（M1）

### 6.1 新增表

```sql
-- 跨章压缩档案（按用户一行）
learner_profiles (
  user_id     TEXT PRIMARY KEY,
  profile_json TEXT,          -- §6.2 结构，≤800 tok
  updated_at  TIMESTAMP
);

-- 长程对话摘要（sliding window 之外回填）
conversation_summaries (
  user_id     TEXT,
  chapter_id  TEXT,
  summary     TEXT,
  updated_at  TIMESTAMP,
  PRIMARY KEY (user_id, chapter_id)
);

-- 全局 Agent 脚手架（决策 Q3 hybrid）：mentor/summary 的对话样本/策略常量/上下文预算/默认钩子
agent_configs (
  name        TEXT PRIMARY KEY,   -- 'mentor' | 'summary'
  config_json TEXT                -- sample_dialogue / exercise_informed_dialogue / context_budget / DEFAULT MENTOR_HOOKS
);
```

保留现有 `step_runs` 结构（原始步骤产出），档案由其派生。

### 6.2 learner_profiles 字段键（必须严格对齐，mentor_hooks.references 锚定这些键）

```
misconceptions_cleared, external_voices, internal_external_ratio, reclaim_item,
likes, talents, importance, work_purpose, values, ranked, intersection,
success_statement, formula, current_chapter, open_questions, milestones
```

### 6.3 compaction 服务

- **触发**：① 某章所有 step 提交后；② 对话累计 K=20 轮（建议值）。
- **策略（混合，已拍板）**：结构化字段（`values`/`work_purpose`/`talents`/`likes`/`formula`/`misconceptions_cleared`/`milestones`）用规则提取；`open_questions` 用廉价 LLM 提取/改写。
- **输出**：≤800 tok，写回 `learner_profiles.profile_json`。
- **必读**：`mentor_design_spec.md` §4（结构）、§9（存储）、§11.1（决策）。

## 7. 逐章实施指南（M4，核心）

### 7.0 每章通用规则（先读，避免重复犯错）

**必读文档（每章都一样）**
- `docs/PRD/PRD-chN.md` —— 整体交互 / 视觉 / **§3.1 LLM 提示词** / 验收。
- `config/chapters/chapter_config_chNN.json` —— `exercises` + `mentor_hooks` + `core_concepts` + `few_shot_examples`。
- `docs/mentor_design_spec.md` —— §5 装配器、§9 数据结构、§12 摘要统一。
- `config/schema/chapter_task_config.schema.json` —— 字段契约。

**步骤实现映射**
- 遍历 `chapter_config_chNN.json` 的 `exercises[]` 数组；**每个 exercise = 一个前端 step 区块**。
- 调用：`agent.run(agent_type="step", chapter_id, step_index, user_input)`。
- 组装 prompt：`system(角色人设+本书背景)` + `user(用户答案)` + **注入该 exercise 的 `few_shot_examples`**（来自 config，不可省略）。
- `user_action` 语义红线：LLM **不替用户下结论**。`assist`=辅助纠正/深化/取交集；`guide`=引导不判断；`none`=纯用户自评。
- `output_fields` → 同时落 `step_runs`（原始）并汇入 `learner_profiles`（按 §6.2 键）。

**`output_fields` 类型化（决策 3，v2.0 已落 schema，见 `config/schema/chapter_task_config.schema.json`）**
- config 中每个字段是对象：`{ "name": "...", "type": "...", "lockable": true/false, "readonly": true/false }`（**向后兼容旧字符串写法**，校验已通过）。本章各表列出的字段名即类型化对象的 `name`。
- 渲染分支（前端 `renderStepOutput` 必须按 `type` 分支）：
  - `editable_list` → 可编辑 chip / 列表（带 `lockable` 锁定、`readonly` 只读排序，如 ch4 `ranked`）；
  - `list` → 只读 chip（如 ch4 `conversions`）；
  - `markdown` / `text` → 文本（如 `commentary` / `work_purpose`）；
  - `table` → 表格（如 ch2 `internal_external_ratio` / ch8 `color_bath_log`）；
  - `json` → 原始 JSON 查看（兜底）。
- **阻塞项**：前端必须补 `groups`(editable_list) / `conversions`(list) 两个渲染分支（ch4 step-2/3），当前硬编码无此分支会退化裸 JSON（见 §7.4）。

**REFERENCES 两种机制（极易混淆，务必区分 —— 对应决策 2 + 评审纠错）**
- ① **章节内级联** = `exercises[].references: [{ from_exercise: "step-1", fields: ["top_values"] }]`：**同一章**内，本步 prompt 注入**前序已提交 step 的 `step_runs.parsed_output`** 指定字段（如 ch4 step-2 需要 step-1 的 `top_values`）。由 `build_step_prompt` 实现，受 ≤3k 护栏约束（按需注入不全量）。
- ② **跨章导师锚点** = `mentor_hooks.references: ["formula"]`：mentor 对话装配时从**跨章 `learner_profiles`** 读取指定档案键。这是跨章连续性，与①无关。
- ⚠️ **别混淆**：另一 Agent review 的 Q2 把①误写成"从 learner_profile 拉"——**以本文①为准**。`groups`/`conversions` 等步骤级中间产物根本不进 profile，从 profile 拉会导致 ch4 级联断裂。
- 角色 system prompt 的**实际文本**在 `PRD-chN §3.1`（如 ch4 的 `psychologist`/`career_counselor`/`mentor`）；config 里的 `core_concepts`/`few_shot` 是上下文层补充。

**mentor 对话接入（每章通用）**
- 入口：右侧「对话」tab + 顶部常驻「问刘老师」+ 每步提交浮层（§8）。
- 调用：`agent.run(agent_type="mentor", chapter_id, user_msg)`。
- 装配：`persona(mentor_config)` + `profile(learner_profiles)` + `hook(chapter_config.mentor_hooks)` + `sliding history(≤12 轮)` + `user_msg`。
- 必读：`mentor_config.json` + `mentor_design_spec.md` §3（人设/策略）、§5（装配）。

**summary 接入（每章通用）**
- 调用：`agent.run(agent_type="summary", chapter_id)`。
- 读 `summary_config.json` 的 `persona` + `output_schema` + `md_cap`(默认 12000) + `per_chapter_focus[chN]`；本章 MD 切片 `[:md_cap]`；可选 profile 增强。
- 输出 `{summary, core_concepts[], key_process[]}`（保持前端兼容）。
- 必读：`summary_config.json` + `mentor_design_spec.md` §12。

## 8. 章末桥接卡（形态 B：回顾卡）组件规范（M5，前端）★决策 A 落点

### 8.1 形态定义

**形态 B = 回顾卡**：章末展示一张"你走到哪儿了"的回顾卡，**默认可见、不强制对话**；提供次要按钮「和刘老师聊聊这一步 ▸」打开 mentor 对话框（带入本章 + 最后一步上下文）。

### 8.2 出现时机

1. 本章**所有 step 提交完成**后，章末区域展示回顾卡。
2. 章首「回顾」链接也可触发同一卡片。
3. 不自动弹窗、不打断阅读。

### 8.3 内容源（来自 profile，非重算）

- 读取 `learner_profiles` 中**该章 `mentor_hooks.references`** 指向的字段（回退：该章 `output_fields`）。
- 展示 2–4 条关键档案字段（键 + 值摘要），标题「📍 我们走到哪儿了」。
- 例：ch04 references=`[formula]` → 展示 `values`/`work_purpose` 摘要；ch07 references=`[work_purpose, talents, likes]` → 展示三要素摘要。

### 8.4 布局与 CTA

- 纸张卡片（复用 ch4 设计系统变量，见下）。
- 主体：2–4 条档案键值（紧凑列表）。
- 底部一行：**次要按钮**「和刘老师聊聊这一步 ▸」→ 打开 mentor 对话（预填 `chapter_id` + 最近 `step_id`），前端随后把 `step_id` 随 `/chat/send` 发送，由后端读取最新 submitted `parsed_output`，不自动发送。
- 无强制、无遮罩。

## 9. 护栏与红线（不可违反）

1. **≤3k token 护栏**：装配后超 3k 先截历史最旧部分，再退化「仅档案+钩子」。**绝不全量注入八章原始 step_runs**。
2. **配置真相在 DB**：`config_loader` 读 DB；JSON 文件仅作 seed 源，运行时**不读 JSON 文件**。
3. **跨章不跨用户**：`learner_profiles` 按 `user_id` 隔离。
4. **刘老师不替用户下结论**；练习中 LLM 按 `llm_role` 仅辅助，不判断对错。
5. **保留旧结构**：新增 `learner_profiles`/`conversation_summaries`，不破坏 `step_runs`。
6. **灰度可回滚**：M3 接入时保留旧 `chat.py`/`summary.py`/`step_runner.py` 路由，可开关切回。
7. **chapter_id 统一**：新配置键用 `ch01`..`ch08`；legacy `seed_ch4.py` 的 `04-important` 必须迁移对齐，避免双标识。
8. **跨步级联走 `exercises[].references` → 前序 `step_runs`**（决策 2）：章节内级联**绝不**从 `learner_profile` 拉（ch4 `groups`/`conversions` 不进 profile）；跨章 mentor 锚点才读 profile。两者机制不同，勿混。

## 14. A方案实现补充：证据绑定与导师收敛（2026-08-05）

本节将 ch01 反馈固化为全书实现约束，不改变前文设计决策：

- 用户答案必须保留逐条结构；ch01 的 `external_voices` 使用误区编号对象，例如 `{"1":"...","3":"..."}`，不得在前端或后端合并成一条字符串。
