> 假设（用户未明确）：UI 形态默认 **A 嵌入式 list + [+] 加行**，管理页位置默认 **A 顶部菜单入口**。用户可在 review 时改。

## 0. 背景与根因

### 0.1 用户报的现象

- 截图：ch02 step-1「内外标准对照」页面，**角色下拉框出现 5 个 career_counselor**（+ psychologist / mentor / summary = 7 项）
- 三个 comment：
  1. 「录一条 → 选外部/内部 → 再录一条 → 再选 → 入库后方便做解析」
  2. 「底部加解释外部/内部驱动 + 例子」
  3. 「这个角色下拉框能不能锁」+「加一个管理界面可以对所有角色 prompt 进行配置和管理」

### 0.2 根因（治本结论）

INSERT `llm_roles` 在应用层只有 **1 个入口**：`POST /api/roles`（前端 `index.html:1473-1486 newRole()` 弹窗）。

截图里 3 条 `career_counselor` (`system_prompt='role'`, length=4) **是用户（或之前 session）通过前端 `newRole()` 手动创建的产品数据**，不是 bug，是产品功能使用痕迹。

但暴露了 2 个后端 bug：
- **Bug A**：`list_roles` 没有按 `(name, provider)` 去重 → 同名多行全部展示 → UI 错乱
- **Bug B**：`create_role` 没有 UNIQUE 约束 → 用户可无限创建同名 role

治本方案：修 Bug A + Bug B（保留脏数据，让 list 展示去重）。

## 1. input_schema 字段定义

### 1.1 位置

在 `chapter_config_chNN.json` 的 `exercises[]` 项里，**与 `output_fields` 并列**：

```json
{
  "step_id": "step-1",
  "name": "内外标准对照",
  "instruction": "...",
  "input_schema": [
    {
      "name": "drive_items",
      "type": "list_of_items",
      "item_schema": {
        "fields": [
          { "name": "text",      "type": "text",   "placeholder": "写下这件事" },
          { "name": "drive",     "type": "select", "options": ["external", "internal"], "labels": { "external": "外部驱动", "internal": "内部驱动" } }
        ]
      },
      "min_items": 1,
      "max_items": 10
    },
    {
      "name": "notes",
      "type": "text",
      "placeholder": "还想补充什么？（可选）"
    }
  ],
  "output_fields": [
    { "name": "internal_external_ratio", "type": "table" },
    { "name": "reclaim_item",            "type": "text", "lockable": true }
  ],
  "step_role_id": "psychologist"
}
```

### 1.2 支持的 input 类型

| type          | 含义                              | 渲染为                            |
|---------------|----------------------------------|----------------------------------|
| `text`        | 单段长文本                        | textarea                          |
| `list_of_items` | 结构化列表，每项含若干 field    | 嵌入式 list + [+] 加行            |
| `select`      | 单选（一般作为 item_schema 子字段）| 下拉/单选按钮组                   |
| `radio`       | 单选（少量 options）              | radio 按钮组                      |

每个 field 通用属性：
- `name`：字段名（用作 JSON key）
- `label`：UI 显示名（缺省用 name）
- `required`：bool，默认 false
- `placeholder`：hint 文本
- `default`：默认值

### 1.3 提交格式

后端 `POST /api/chapters/{ch}/steps/{step}/draft` 的 `user_answers` 字段从现在的 `["一段文本"]` 改成对象：

```json
{
  "user_answers": {
    "drive_items": [
      { "text": "加班做项目", "drive": "external" },
      { "text": "学新东西",    "drive": "internal" }
    ],
    "notes": "周末想写点东西"
  }
}
```

`step_runs.user_answers` 列存 JSON 字符串（列定义已允许 TEXT，schema 不需改）。

### 1.4 LLM 接收格式

`agent.run_step` 把 `user_answers` dict 序列化成 prompt 友好的 markdown：

```markdown
## 用户输入（按字段）

**事项清单（drive_items，共 2 条）：**
1. text="加班做项目" drive=external
2. text="学新东西" drive=internal

**备注（notes）：**
周末想写点东西
```

不破坏现有 build_step_prompt；只在 user_answers 渲染层加一层 helper。

## 2. UI 控件设计（按 type 渲染）

### 2.1 text

```html
<div class="q">
  <div class="qt">1. 写下这件事</div>
  <textarea placeholder="..."></textarea>
</div>
```

### 2.2 list_of_items（核心）

```html
<div class="q">
  <div class="qt">事项清单（至少 1 条）</div>
  <div class="items-list">
    <div class="item-row" data-idx="0">
      <input class="item-text" placeholder="写下这件事" />
      <div class="item-drive">
        <label><input type="radio" name="drive-0" value="external" /> 外部驱动</label>
        <label><input type="radio" name="drive-0" value="internal" /> 内部驱动</label>
      </div>
      <button class="item-del" onclick="delItem(0)" title="删除">×</button>
    </div>
    <div class="item-row" data-idx="1"> ... </div>
  </div>
  <button class="item-add" onclick="addItem()">+ 添加一项</button>
</div>
```

行为：
- 初始渲染 1 条空行（min_items=1）
- `[+]` 加一行（直到 max_items）
- `×` 删当前行（至少保留 min_items 行，删到 min_items 时按钮 disabled）
- 提交时按 DOM 顺序收集 `{text, drive}` 数组

### 2.3 select（item_schema 子字段）

```html
<select>
  <option value="external">外部驱动</option>
  <option value="internal">内部驱动</option>
</select>
```

### 2.4 radio（item_schema 子字段或顶层）


## 3. 锁角色交互（comment 3）

### 3.1 决策

**步骤内 dropdown 锁定为 `step_role_id`**，禁用 + tooltip「题目已指定角色：psychologist」。理由：
- chapter config 的 `step_role_id` 是设计侧定的，针对该 step 优化 system_prompt
- 改选会切到不针对该 step 优化的角色，**LLM 仍能输出对 schema 但质量下降**
- harness summary 已点出 ch07/ch08 在 fallback 到 career_counselor 是语义略粗，本轮目标是**收紧而非放开**

### 3.2 实现

`renderStepBody(step)`：

```js
const isLocked = step.llm_op?.role_id_locked !== false; // 缺省锁
const selectHtml = `
  <div class="role-line">
    角色 <select id="role-${step.step_id}" ${isLocked ? 'disabled' : ''}>
      ${roleOptions}
    </select>
    ${isLocked ? '<span class="lock-hint">🔒 题目指定</span>' : ''}
  </div>`;
```

每个 step 默认锁；`chapter_config.exercises[].allow_role_override: true`（缺省 false）开启解锁。

`/api/chapters/{ch}/steps/{step}/run` 也校验：若 `allow_role_override=false` 而 body 含 `role_id` → 400。

### 3.3 不影响

- 顶部「角色浮窗」（`renderRoleFloat`）仍可改全局默认 role，用于 chat / summary
- 步骤内的 role 只受 `step_role_id` 锁定

## 5. 后端治本修复

### 5.1 Bug A：`list_roles` 去重

修改 `app/routers/roles.py`：

```python
@router.get("")
def list_roles(enabled_only: bool = False, group_by_name: bool = False):
    with get_conn() as conn:
        if group_by_name:
            # 取 (name, provider) 分组中 created_at 最新的一行作为代表
            sql = """
                SELECT r.* FROM llm_roles r
                JOIN (
                    SELECT name, provider, MAX(created_at) AS max_at
                    FROM llm_roles
                    {where_enabled}
                    GROUP BY name, provider
                ) m
                  ON r.name = m.name AND r.provider = m.provider AND r.created_at = m.max_at
                ORDER BY r.created_at
            """.format(where_enabled="WHERE enabled = 1" if enabled_only else "")
            rows = conn.execute(sql).fetchall()
        else:
            sql = "SELECT * FROM llm_roles {where} ORDER BY created_at".format(
                where="WHERE enabled = 1" if enabled_only else "")
            rows = conn.execute(sql).fetchall()
    return [dict(r) for r in rows]
```

默认行为不变（`group_by_name=False`）；角色管理页请求时传 `?group_by_name=true`。

### 5.2 Bug B：`create_role` UNIQUE 约束

加表级约束（migration 脚本）：

```sql
CREATE UNIQUE INDEX IF NOT EXISTS idx_llm_roles_name_provider_enabled
  ON llm_roles (name, provider) WHERE enabled = 1;
```

**注意**：当前 4 条 career_counselor 都在 `enabled=1`，加约束前必须**先禁用/合并重复行**（本期不自动合并，先手动 `UPDATE enabled=0 WHERE id IN (...)`，等用户 review）。

新 `create_role` 加检查：

```python
@router.post("")
def create_role(body: RoleIn):
    with get_conn() as conn:
        existing = conn.execute(
            "SELECT id FROM llm_roles WHERE name = ? AND provider = ? AND enabled = 1",
            (body.name, body.provider),
        ).fetchone()
        if existing:
            raise HTTPException(409, f"role {body.name} ({body.provider}) already exists")
        ...
```

### 5.3 不动数据

当前 4 条 career_counselor：
- `id=6907fbb0` L=1460 设计侧 long-form → **保留**
- `id=22d4da6e, b4754537, e23ad451` L=4 用户手动 'role' → **保留但通过管理页建议用户处理**

本期不自动删/合并，给用户**管理权**。

## 7. 风险点

1. **input_schema 升级到 8 章**：每章 design 都要填 `input_schema[]`，否则前端 fallback 到旧 `user_input.questions` 渲染。建议：分批 — 先 ch01/ch02（用户已报问题的两章），其他章待设计侧 review
2. **后端 user_answers 兼容**：旧 draft 存的是 string 列表，新代码要兼容 `["str"]` 和 `{key: value}` 两种 schema
3. **UNIQUE INDEX 加上后**：用户再次通过前端 `newRole()` 创建同名 → 409 → UI 要给出友好提示「已存在，去管理页编辑」
4. **锁角色**：用户可能有「我就是想试试其他角色」的场景；`allow_role_override: true` 字段给设计侧留口子
