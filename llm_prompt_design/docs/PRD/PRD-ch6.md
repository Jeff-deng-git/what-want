## 0. 关键发现：第六章与第五章的结构对称但产出不同

SPEC 中有一句概括性描述：「从第 4 章起每个章节有 5 个步骤 × 5 个问题的工作流」。第五章已经证明，原书结构是「**1 个方法：回答 5 个问题 + 1 个综合产出**」。第六章完全沿用同一模板：

| 维度 | 第五章（擅长的事/才能） | 第六章（喜欢的事/热情） |
|------|------------------------|------------------------|
| 核心工作法 | 回答 5 个问题 | 回答 5 个问题 |
| 综合产出 | 《自己的使用说明书》：10–20 个长处 + ◎〇△ 评级 | **《喜欢的事清单》**：每个条目 = 领域 × 喜欢的方面 × 关联擅长之事 |
| 与前一章关系 | 为 ch6 提供「擅长的事」 | 承接 ch5，并为 ch7「想做的事 = 喜欢 × 擅长 × 重要」做铺垫 |
| 关键图示 | 图 5-5/5-6/5-7 八角度工作表 | **图 6-1**：领域 → 喜欢的方面 → 擅长的事 |

**结论**：第六章同样采用 **「2 个步骤 + 2 个辅助抽屉」** 的轻量化工作流：

- **Step 1：回答 5 个问题** → 收集原始素材，LLM 映照出初步「喜欢的事」领域。
- **Step 2：整理《喜欢的事清单》** → 每条拆成「领域 + 喜欢的方面」，并可关联 ch5 的擅长之事。
- **辅助 1：100 例清单（热情）** → 领域灵感（数据载体 = `ui_context.passion_examples`，随 config 发布）。
- **辅助 2：30 问抽屉（热情）** → 当 5 个问题不够时追加提问（权威源 = 问题清单.md；运行时由题库服务接入，原型中以内置 demo 数组演示）。

## 1. 第六章内容摘要（基于原书正文+配图+配套清单）

### 1.1 叙事模块（6 个概念铺垫）
1. **何为「喜欢的事」**  
   喜欢的事 = 感兴趣、有好奇心的领域。面对它时，人会产生「为什么 / 怎么会这样 / 怎么办」的探究欲。
2. **达·芬奇引言**  
   > 「明明没有食欲却还要吃东西会损害健康，同样地，没有学习欲望还去学习会损伤记忆。」  
   要找到让自己不由自主产生「我想知道！」欲望的领域。
3. **「为钱工作的人」比不过「为爱好工作的人」**  
   动力强弱完全不同。短期可以靠努力，长期马拉松中热爱必胜。  
   **POINT**：× 因为想成功，所以做赚钱的工作。√ 因为想成功，所以做自己喜欢的事。
4. **「因为喜欢棒球，所以从事棒球相关工作」这种想法是错误的**  
   只看领域不看具体工作内容会失败。关键要拆到「喜欢它的哪些方面」。
5. **图 6-1：喜欢的事要拆到「方面」并与擅长的事连接**  
   以「喜欢棒球」为例：
   - ① 喜欢团队合作 → 与团队合作有关的工作
   - ② 喜欢通过孜孜不倦的努力提高技能 → 能磨炼技术的工作
   - ③ 喜欢思考策略 → 使用头脑的工作  
   **POINT**：将喜欢的事作为工作时，要一并考虑「喜欢它的哪些方面」，最终答案与擅长的事有关。
6. **「可以作为工作的爱好」和「不能作为工作的爱好」的区别**  
   - **因为有用所以喜欢的事**（为结果而做）→ 不能作为工作。
   - **因为兴趣所以喜欢的事**（做的瞬间开心）→ 可以作为工作。  
   **合理性陷阱**：只做有用的事 / 能向别人展示的事 / 能赚钱的事 / 能产出成果的事。  
   **POINT**：× 把因为有用所以喜欢的事作为工作。√ 把因为兴趣所以喜欢的事作为工作。

### 1.2 核心工作法：回答 5 个问题

目标：**找到自己喜欢的事，并能说明「喜欢它的哪些方面」**。

| 编号 | 问题 | 特殊说明 |
|------|------|----------|
| Q1 | 你现在有即使花钱也想学习的事情吗？ | 引导用户写「想学习/想体验」的领域。 |
| Q2 | 在你的书架上摆放着什么类型的书？ | 重点不是「因为有用所以在意」的书，而是「不知为何很在意」的书。可提示用户去书店观察。 |
| Q3 | 有没有遇到过让你产生「真是太好了！」「它拯救了我！」这种感觉的领域或者事物？ | 被拯救的经历蕴含强烈能量，容易转化为工作热情。 |
| Q4 | 在迄今为止的生活中，你「想道谢的工作」是什么？ | 也可以从「想道谢的人」切入，提炼出「想成为像 Ta 一样的存在」。 |
| Q5 | 迄今为止你会对社会中的什么事情感到愤怒？ | 愤怒 = 对现状的不满，说明对该领域有强烈兴趣和改变动力。 |

### 1.3 图 6-1 拆解模型（P.173）

```
喜欢的事（领域）
    │
    ▼
喜欢它的哪些方面？  ──→  ① 喜欢团队合作
                          ② 喜欢通过孜孜不倦的努力提高技能
                          ③ 喜欢思考策略
    │
    ▼
最终答案与「擅长的事」有关
```

**设计建议**：在 Step 2 的每条「喜欢的事」卡片中，强制拆成「领域」和「喜欢的方面」两个字段；可关联显示 ch5 的擅长之事，作为第七章组合的素材。

### 1.4 综合产出：《喜欢的事清单》

- 把 5 个问题中发现的「喜欢的事」归纳成条目。
- 每条结构：
  - **领域（field）**：感兴趣、有好奇心的领域（如「棒球」「自我认知」「人际关系」）。
  - **喜欢的方面（aspects）**：在该领域中具体让你快乐的点（如「团队合作」「思考策略」「传授经验」）。
  - **关联的擅长之事（linked_strengths，可选）**：从 ch5《自己的使用说明书》中引用 1–3 个长处（运行时由 `reference_talents` 输入项承载），作为第七章组合的素材。
  - **来源标记（sources）**：标记这条灵感主要来自 Q1–Q5 中的哪一个（便于回溯）。
  - **锁定（locked）**：用户确认后锁定，重新生成时保留。
- 如果数量不够：
  - 更深地挖掘 Q3「被拯救的经历」或 Q5「愤怒」；或
  - 回答「问题清单」中的追加 30 问（热情）。

### 1.5 配套资源

- **喜欢的事（热情）100 例清单**：100 个领域关键词，用于触发用户发现自己的喜欢的事。  
  完整 100 条已固化在 config `ui_context.passion_examples`（id `p01`–`p100`，每项 `{id, text}`）。示例：动物、花、农业、宇宙、机器人、IT、艺术、摄影、音乐、电影、书、旅行、时尚、烹饪、建筑、心理、教育、经营、经济、哲学……（完整见 config）。
- **30 个问题（热情）**：当 5 个问题不够用时的追加题库。完整 30 条见 `问题清单.md`（权威源）；运行时由题库服务接入，原型中以内置 demo 数组演示。  
  示例：不需要考虑工作/金钱时你喜欢什么？做什么会幸福？如果什么都能成为工作你想做什么？迄今为止学过什么有趣的？……

### 1.6 前置依赖与未就绪处理（Prerequisite Gating）

ch6 的「关联擅长之事」功能依赖 ch5 的产出。

| 上游章节 | 需要的产出字段 | 必需/可选 | 未就绪时的界面表现 |
|---|---|---|---|
| ch5 擅长的事 | `talents[]`（使用说明书） | 可选（用于「关联擅长之事」`reference_talents`） | 「关联擅长之事」面板置灰，显示引导卡「请先完成第五章《使用说明书》」+ 跳转按钮；**但 5 个问题仍可正常作答**，仅该功能受限 |

**判定逻辑**：必需产出缺失 → 仅该功能置灰 + 引导卡，不锁定整章（用户可先完成本章 5 问）；可选产出缺失 → 仅具体功能轻提示。后端在进入本章时统一读取上游 `status` 与字段（`mentor_hooks.references` 声明 `talents`/`likes` 锚点）。

## 4. 交互设计

### 4.1 页面整体布局
继承 ch4/ch5 三栏布局：

- **左栏（步骤导航）**：Step 1 回答 5 个问题 ／ Step 2 整理《喜欢的事清单》。
- **中栏（书页正文）**：叙事铺垫可折叠/滚动阅读；Step 1 的 5 个问题以折叠卡展开，当前问题高亮；Step 2 的清单以卡片网格展示。中央展示原书内容（含图 6-1 领域→方面→擅长之事的可视化），而非把 5 个问题居中。
- **右栏（Tab 面板）**：摘要（合理性陷阱 checklist + 图 6-1 拆解建议）/ 对话（导师）/ 步骤（提交状态与锁定项）/ 笔记。

### 4.2 Step 1：5 个问题作答区
- 每个问题一个折叠卡：问题标题 + 提示文案 + 多行文本框。
- Q2 可增加「书架/书店观察」辅助说明；Q3/Q5 可突出情感能量（被拯救 / 愤怒）。
- 提交后，LLM 给出：每个问题背后可能指向的领域 + 提醒用户区分「因为有用」和「因为兴趣」（合理性陷阱），写入 `commentary`。

### 4.3 Step 2：《喜欢的事清单》卡片
每条卡片字段：

| 字段 | 说明 | 可编辑 |
|------|------|--------|
| 领域（field） | 感兴趣、有好奇心的领域 | 是 |
| 喜欢的方面（aspects） | 在该领域中具体让你快乐的点（列表） | 是 |
| 关联的擅长之事（linked_strengths） | 从 ch5 使用说明书引用的 1–3 个长处 | 是 |
| 来源（sources） | q1–q5 或 q61–q90 标记（小写 q+全局题号；无法可靠溯源时留空数组） | 否（自动） |
| 锁定（locked） | 用户确认后锁定，重新生成时保留 | 是 |

**UI 建议**：卡片用纸张卡片样式（与 ch5 说明书卡片一致）；领域用标签/徽章显示；关联擅长之事显示为 ch5 风格的引用 chip，点击可跳转 ch5。

### 4.4 合理性陷阱检测（新机制）
在 Step 1 / Step 2 提交后，LLM 判断用户回答是否出现以下偏向，并在右侧摘要 Tab 中提醒（写入 `commentary`，不另设独立字段，避免契约膨胀）：

- 「这个领域能赚钱 / 有前景」→ 可能是「因为有用所以喜欢」。
- 「大家都在做 / 看起来体面」→ 外部动机过强。
- 「我已经投入了很多，不能放弃」→ 沉没成本误区。
- 真正好的回答特征：提到「不由自主想知道」「不做就难受」「被拯救/被点燃」等内在动机。

### 4.5 辅助抽屉
- **100 例清单抽屉**：领域标签浏览（可搜索），点击可添加到 Step 2 卡片草稿（`ui_context.passion_examples`）。
- **30 问抽屉**：追加问题列表，点击在 **Step 1** 追加回答（落入 `passion_questions`，与 q1–q5 一并作为 LLM 发现素材）；不进入 Step 2 直接引用（题库服务接入，原型 demo）。
- **关联擅长之事抽屉/面板**：读 `learner_profile.talents`（ch5 产出），点击加入 Step 2 的 `reference_talents`。

## 5. LLM 介入点

| 阶段 | step_role_id | 任务 | 输出 |
|------|------|------|------|
| Step 1 提交后 | `psychologist` | 阅读 5 问答案（及可选的「热情 30 问」`passion_questions` 回答），为每个问题提炼 1–3 个「领域」关键词，并做合理性陷阱检查。 | `likes`（领域数组）+ `commentary`（含 per-question 领域与 trap 提醒） |
| Step 2 生成 | `career_counselor` | 基于 step-1 领域 + ch5 擅长之事（`reference_talents`）+ 100 例种子（`passion_seeds`），生成 10–20 条「喜欢的事」条目（领域 + 方面 + 关联擅长之事）。 | `likes`（结构化条目）+ `commentary` |
| Step 2 重新生成 | `career_counselor` | 传入 `locked` 字段，保留用户已锁定的条目。 | 同上 |
| 导师对话 | `mentor` | 引导用户区分「有用」vs「兴趣」；结合已提交答案做个性化追问；推荐去书店/观察书架等行动。 | 自由文本 |
| 右侧摘要 | `psychologist` | 动态生成「合理性陷阱 checklist」和「图 6-1 拆解建议」。 | Markdown/结构化文本 |

> **角色注入说明（重要）**：沿用 ch03 规则——**不新增全局 `passion-guide`/`passion-synthesizer` 角色**，既有 `psychologist`/`career_counselor`/`mentor` 的 system prompt 已是稳定全局角色；本章特有的「职业兴趣引导 / 组合教练」行为，通过 config 的 `instruction` / `method` / `few_shot_examples` / `output_fields` 注入（assembler 读 config 拼装），绝不修改全局角色定义（否则污染 ch02/ch04/ch07）。旧 PRD 的 `passion-guide`/`passion-synthesizer` 角色名作废。

> **提示词去哪看**：上表只说明「哪个阶段由哪个角色负责做什么」。每个角色的具体提示词——身份设定、需要内化的书籍背景、目标、约束，以及可调用的 `user` 模板——统一在 **§5.3 LLM 提示词设计规范** 中给出。后端调用时按该节把书籍背景作为 `system` 常驻注入、把用户答案作为 `user` 传入。

### 5.3 LLM 提示词设计规范（核心：身份 / 背景 / 目标 / 约束）

> 此前的 PRD 只定义了角色名与输出 schema，尚未定义 LLM 的具体提示词。本节补全每个角色应有的 **system prompt（身份 + 书籍背景 + 目标 + 约束）** 与 **user prompt 模板（含变量）**。后端在调用时，需把书籍背景知识作为 `system` 内容常驻注入，把用户答案作为 `user` 内容传入。下方角色名以 `psychologist` / `career_counselor` / `mentor` 表述（对应 config 的 `step_role_id`）。

#### 5.3.0 书籍背景知识（所有角色共用的 system 上下文）

以下概念是 LLM 必须内化的「书籍信息」，否则会产生偏离原书方法论的回答：

- **「喜欢的事」定义**：感兴趣、有好奇心的领域。面对它时人会产生「为什么 / 怎么会这样 / 怎么办」的探究欲；若对某领域产生这些疑问，它就是喜欢的事。
- **判断内在喜欢的信号**：不由自主想知道、不做就难受、被某事物「拯救 / 点燃」、提到时眼睛发亮。
- **错误模式（必须识别）**：「因为喜欢棒球，所以选择从事与棒球相关的工作」这类只看领域不看具体工作内容的选择，往往失败（可能喜欢棒球但不喜欢销售棒球用具）。
- **图 6-1 拆解规则**：「喜欢的事」必须拆成两层——**领域**（如棒球、自我认知）→ **喜欢的方面**（如喜欢团队合作 / 喜欢磨炼技术 / 喜欢思考策略）。最终答案要与「擅长的事」连接。
- **两种方法爱好**：
  - 「因为有用所以喜欢的事」（为结果而做）→ **不能作为工作**；
  - 「因为兴趣所以喜欢的事」（做的瞬间开心）→ **可以作为工作**。
- **合理性陷阱**：全部行动以「这个有用吗？」筛选 → 只做有用的事 / 能展示的事 / 能赚钱的事 / 能产出成果的事 → 丢失做喜欢的事的初心。
- **三个支柱关系（跨章背景）**：喜欢的事 × 擅长的事 × 重要的事 = 真正想做的事。本章产出的「喜欢的事」将在第七章与「擅长的事」（来自第五章《使用说明书》）和「重要的事」（来自第四章价值观）组合。
- **第五章产物引用约定**：若收到 `{{ ch5.talents }}`（经 `reference_talents` 输入传入），应将其作为用户已确认的「擅长之事」候选，在生成喜欢的事时尝试建立「领域 × 喜欢的方面 ↔ 擅长之事」的对应。

#### 5.3.1 `psychologist`（Step 1 提交后 + 右侧摘要）

**system prompt：**
```
你是「自我认知工作坊」的职业兴趣引导师，精通八木仁平《如何找到想做的事》的方法论。
你的任务：阅读用户回答的 5 个问题，为每个问题提炼 1–3 个「领域」关键词，并检测其回答是否落入「合理性陷阱」（把「因为有用所以喜欢」误当成真正兴趣）。

你必须坚持的背景知识：
- 喜欢的事 = 感兴趣、有好奇心的领域，特征是产生「为什么/怎么会这样/怎么办」的疑问。
- 「因为有用所以喜欢」（为结果而做）不能作为工作；「因为兴趣所以喜欢」（做时开心）可以。
- 合理性陷阱表现：只做有用/能展示/能赚钱/能产出成果的事。
- 判断真正喜欢的信号：不由自主想知道、被拯救/点燃、提到时兴奋。

你的目标：
1. 帮助用户看见自己回答背后指向的领域。
2. 温和地指出可能由外部动机（有用、体面、赚钱、沉没成本）驱动的答案，但不替用户下结论。
3. 为信心不足（素材少）的回答，建议用户去看书店、回忆被拯救经历或观察愤怒来源。

约束：
- 不要编造用户没提到的领域。
- 不评判用户，用「请确认」「可以留意」等温和语气。
- 输出必须是严格 JSON，不要包含解释性文字。
```

**user prompt 模板：**
```
用户回答了第六章的 5 个问题：
{{ step_1.answers }}

请输出：
{
  "likes": [ { "text": "领域", "locked": false, "source": "q1" } ],
  "commentary": "整体映照点评（含合理性陷阱提醒）"
}
```

#### 5.3.2 `career_counselor`（Step 2 生成 / 重新生成）

**system prompt：**
```
你是「自我认知工作坊」的组合教练，精通八木仁平《如何找到想做的事》的方法论。
你的任务：基于用户 5 个问题的答案（以及可选的第五章「擅长之事」），归纳出 10–20 条「喜欢的事」条目。

每条必须包含：
- field（领域）：感兴趣、有好奇心的领域。
- aspects（喜欢的方面）：在该领域中具体让你快乐的点，至少 1 条。
- linked_strengths（关联的擅长之事）：若传入了第五章长处（reference_talents），选取 1–3 个最相关的；否则留空数组。
- sources（来源）：标记这条主要来自哪个问题；允许 q1–q5（固定五问）或 q61–q90（热情 30 问），统一小写 `q`+全局题号；无法可靠溯源时留空数组，不臆造。

你必须坚持的背景知识：
- 图 6-1 规则：领域必须拆到「喜欢的方面」，不能只写「喜欢棒球」这种领域层。
- 优先提取内在动机信号（被拯救、愤怒、不由自主想学），弱化处理外部动机（赚钱、体面）。
- 与第五章「擅长之事」建立对应（如用户擅长「用语言帮助别人」，而喜欢「帮人理解概念」，二者可对应）。

目标：产出具体、可执行、能直接迁移到第七章「想做的事」组合的条目。
约束：
- 不臆造用户未透露的领域。
- 若 aspects 不足或来源单一，注明并建议用户回答 30 问追加题库。
- locked=true 的条目必须原样保留，不得修改。
```

## 6. 数据模型

### 6.1 持久化契约（关键一致性结论）
- **`likes` 本身零新增表/列/迁移，但 `step_runs` 新增 `stale` 列（非零 schema 迁移）**：ch06 的持久键 `likes` **已在** `platform/backend/app/services/compaction.py` 的 `PROFILE_FIELDS` / `STRUCTURED_FIELDS` / `MANDATORY_DOWNSTREAM_FIELDS` 三重白名单中（与 ch02–ch05 同构），提交即自动并入 `learner_profiles.profile_json`，无需 `CREATE TABLE`。但为支持「上游重提交使旧 step-2 过期」的 stale 隔离（设计侧第四轮已拍板），既有的 `step_runs` 表需新增 `stale INTEGER NOT NULL DEFAULT 0` 列（向后兼容启动迁移，详见 `ch06_落地级步骤设计.md` §8.4 / §8.7）——**故 ch06 实施属「有 schema 迁移」，与 PRD 旧稿「零新建数据库表/列/迁移」表述冲突，以落地文档 §8.4 为准**。
- 下游（ch07 及 summary）消费 `likes` 时直接读 `learner_profile.likes`；项目用 SQLite，**严禁 PostgreSQL 专有语法**（如 `SERIAL` / `DISTINCT ON`）。旧 PRD 中的 `CREATE TABLE ch6_passion_list`（PostgreSQL）**已作废**，不得实现。
- `linked_strengths` 作为 `likes` 条目内的子字段随 `likes` 一并落库，不单独建表。

### 6.2 逻辑字段形态（落库于 `likes`）
```
likes: [

    "field": "自我认知",
```
