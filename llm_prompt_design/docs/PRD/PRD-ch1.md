## 0. 关键发现：第一章是全书认知起点，不是「弱章」

在「全书统一重构」视角下，ch1–ch8 不是 8 个孤立 PRD，而是**一条认知流水线**：

```
ch1 解构误区 → ch2 区分内外标准 → ch3 建立三要素公式
   → ch4 价值观/工作目的 → ch5 擅长 → ch6 喜欢 → ch7 组合 → ch8 实践
```

ch1 处于流水线最前端。它本身只有**一个轻量练习（误区自检清单）**，不构成强流程（不像 ch4 的 5 步级联）。但它的产出——「用户中招了哪些误区 + 背后的外部声音」——会被刘老师在 ch2/ch3 引用，用来解释「你为什么用外部标准做选择」「你为什么迟迟不敢行动」。所以 ch1 是**全书跨章连续性的第一个支点**。

> ⚠️ **重构提示**：当前 `platform/backend` 只 seed 了 ch4，ch1–ch3 的配置（`config/chapters/chapter_config_ch01.json` 等）尚未灌入 DB，因此产品里前三章只有硬编码的「摘要 + 刘老师对话」。本次重构需为 ch1–ch3 补 seed，并把其产出映射到 `learner_profiles` 表（详见《全书重构设计总览》）。

## 1. 第一章内容摘要（基于正文 + 配套清单）

### 1.1 五大误区（认知拆解的核心）

| 编号 | 误区（错误认知） | 正确认知 |
|------|----------------|---------|
| ① | 必须是能坚持一生的事 | 做“现在最想做的事”就可以了 |
| ② | 找到想做的事时会有命中注定的感觉 | 即使找到了想做的事，一开始也只是处在感兴趣的阶段 |
| ③ | 必须是对别人有益的事 | 为自己而活也是在帮助别人 |
| ④ | 必须多行动才能找到 | 了解自己才能找到想做的事 |
| ⑤ | 想做的事不能成为工作 | 想做的事在自己心中，实现手段在社会中 |

**POINT**：找不到想做的事，往往不是能力问题，而是被误区困住；误区的本质是用「外部标准」替代了自我认知。

### 1.2 配套资源

- **误区自检清单**：用户对照 5 个误区，标记自己中招的条目，并写下每条背后的「外部声音」（如「我爸总说选错行一辈子完了」）。
- 作者案例：八木本人也曾陷误区②（靠直觉），正因为没有直觉才发明了方法——说明误区②本身是「假前提」。

## 2. 可设计成互动的部分

### 2.1 通用阅读层（与 ch4–ch8 一致）

- 三栏布局：左步骤导航 / 中正文 / 右 tab 面板（摘要 / 对话 / 步骤 / 笔记）。
- 正文可选中记笔记；目录下拉含本章 h2 锚点；进度保存上次阅读位置。

### 2.2 本章练习（轻量，1 个）

#### 误区自检清单

- 页面结构：
  - 顶部：5 个误区卡片，每张显示「❌错误认知 ↔ ✅正确认知」对照（源自正文表 1-1 的 5 行）。
  - 每张卡片下方：一个勾选框「我中招了」+ 一个短文本「背后的外部声音」。
  - 底部：「提交自检」按钮。
- 提交后 LLM 输出 `commentary`（整体映照点评）+ 提取 `misconceptions_cleared`（中招的误区编号）+ `external_voices`（用户写下的外部声音）。
- **不强制**进入刘老师对话（刘老师为 opt-in 可选层，见《全书级导师设计规范》）。

### 2.3 右侧 tab 面板

| tab | 第一章内容 |
|-----|-----------|
| 摘要 | 基于本章 MD 生成：五大误区对照、误区本质（外部标准替代自我认知）、「先从重要的事开始」的伏笔 + 关键流程编号。 |
| 对话 | 导师「刘老师」多轮对话，可基于自检结果做苏格拉底追问（如「你勾了①，那背后那个『必须一次找对』的声音，最近一次让你停下了什么？」）。 |
| 步骤 | 误区自检清单 runner，显示提交状态。 |
| 笔记 | 选区笔记 + 独立笔记。 |

### 2.4 导师「刘老师」融合设计（mentor）

> 刘老师是贯穿全书的常驻导师，配置见 `config/mentor/mentor_config.json`，运行时由统一 Agent「导师模式」加载；本章通过 `mentor_hooks` 声明聚焦点。详见 `docs/mentor_design_spec.md`。

- **knows**：book_md（本章正文）+ user_progress（误区自检答案：中招编号、外部声音）+ conversation_history。
- **grounding_rules**：只基于本章展开；引用用户自检里写下的原话；一次只聚焦一个点；不替用户下结论。
- **示例对话**（取自 `mentor_config.json` 的 `exercise_informed_dialogue`）：
  - 用户 ch1 自检标记中招①「唯一正确的事」+ 外部声音「父亲的选错行说教」→ 刘老师在后续对话引用此锚点。

## 3. 需要大模型介入的部分

| 场景 | LLM 角色 | 作用 | 输出位置 |
|------|---------|------|---------|
| **误区自检辅助** | psychologist / 通用教练 | 读用户勾选 + 外部声音，给出映照点评，提取中招误区。 | 步骤的 commentary + misconceptions_cleared + external_voices |

## 4. 推荐的工作流配置（chapter_config JSON）

> 等价于 `config/chapters/chapter_config_ch01.json`（已含 `mentor_hooks` + 练习交互字段）。重构时以该文件为「上下文层」配置源，由统一 Agent 运行时拼装。

```json
{
  "chapter_id": "ch01",
  "chapter_title": "阻碍找到想做的事的5种误区",
  "exercises": [
    {
      "name": "误区自检清单",
      "instruction": "对照五大误区，标记自己中了几条，并写下每条背后那个『外部声音』。",
      "worksheet": "误区1–5：中/不中 + 我当时怎么想",
      "user_action": "用户勾选自己中招的误区条目，并自由写下每条背后的外部声音来源。LLM 不替用户判断是否『真中招』——这是用户自评。",
      "llm_role": "assist",
      "output_fields": ["commentary", "misconceptions_cleared", "external_voices"],
      "few_shot_examples": [
        {
          "user": "我勾了①『必须有唯一正确的事』和③『必须从喜欢开始』。①是因为我爸总说『选错行一辈子完了』；③是我自己觉得不确定喜欢啥就什么都不敢试。",
          "assistant": "这两条其实连着——『怕选错』让你不敢试，于是用『先找喜欢』当拖延借口。你爸那句『选错行』是典型的外部标准。书里说，先做个『现在最想试的小事』就行，不用定终身。你最近有哪个小念头一直被这两条压着？"
        }
      ]
    }
  ],
  "mentor_hooks": {
    "focus": "解构『想做的事』的常见误解，确认起点",
    "references": []
  }

```

> `output_fields` 直接对齐 `learner_profile` 键，为本章产出落地做准备。

## 5. 数据模型与输出 schema

### 5.1 误区自检输出

```json
{
  "commentary": "你勾了①和③，背后都指向『怕选错』这个外部声音……",
  "misconceptions_cleared": ["①唯一正确的事", "③从喜欢开始"],
  "external_voices": ["父亲的选错行说教"]
}
```

- `commentary`：映照点评（markdown）。
- `misconceptions_cleared`：用户中招的误区编号/标签，汇入 `learner_profile`。
- `external_voices`：用户写下的外部声音来源，汇入 `learner_profile`，供刘老师后续引用。

## 11. 反馈修订条款（2026-08-05）

- 交互顺序为：填写 5 张独立误区卡 → 运行 LLM → 查看针对用户答案的 commentary → 提交 → 可进入「对话」tab；填写阶段不显示「聊聊这一步」。
- `commentary` 必须围绕每个勾选误区，结合对应外部声音和本章正文进行解释，不得写成泛化章节摘要或只复述用户输入；前端不得重复渲染同一批输入。
- 刘老师必须用自己的话理解并解释书中原则，结合用户问题和上下文引导；不得使用「书中说」「作者说」「本章写到」等照本宣科表达。

## 12. A方案实现验收补充（2026-08-05）

- `external_voices` 必须按误区编号保存为对象，例如 `{"1":"...","3":"..."}`；每张误区卡独立勾选、独立填写，LLM 只分析已勾选条目。
- `commentary` 必须逐条结合用户声音和本章正文完成分析：说明外部声音如何形成压力、如何造成卡点、如何用本章观点重构，并给出一个观察或低成本行动。
- 刘老师对话必须以当前误区为 active focus，先回应再提问；同一焦点最多连续追问两轮，用户问行动时先给行动，明确切换前不得自行换误区；不得使用“书中说”“作者说”“本章写到”等照本宣科表达。
- 验收不只检查页面流程成功，还要检查前一步输出是否实际进入后一步 prompt；缺失上下文时应阻断而不是生成看似完整的回答。
