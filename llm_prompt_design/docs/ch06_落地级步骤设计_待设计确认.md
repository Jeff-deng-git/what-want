## 0. 终审结论

当前 chapter_config_ch06.json 已切换到最终设计的 2 步结构，主方向正确：

- step-1：psychologist，回答 q1–q5，输出领域级 likes；
- step-2：career_counselor，引用 step-1 的 likes，可选接收 ch05 的 reference_talents，输出结构化 likes；
- ui_context.passion_examples 已有 100 条；
- mentor_hooks.references 为 talents、likes；
- step_context.references 与 ui_context.references 为空，符合“导师钩子不泄漏到普通步骤 Prompt”的设计。

但是，当前生产代码和页面没有形成与该配置对应的完整闭环：

- 后端只有 ch05 专属级联/规范化/校验逻辑，没有 ch06 对应实现；
- 前端只有 ch05 专属 renderer，没有 renderCh06StepBody；
- 通用 renderer 会把 ch06 的嵌套 likes 降级为 JSON 字符串，无法实现领域、方面、关联擅长、来源、锁定的编辑体验；
- passion_examples 已在 config 中，但步骤 API 的 ui_context 构造目前只处理 strength_examples，不会把 100 例传给前端；
- 聊天路由目前只对 ch04/ch05 使用完整 submitted-only chapter loader，ch06 仍走单 step loader，与 ch06 导师读取本章所有已提交步骤的契约不完全一致；
- 全书测试已按 ch06 两步配置迁移，但没有覆盖 ch06 设计要求的完整契约。

因此，当前不能把 ch06 视为已完成，也不能把本轮描述为 ch05/ch06 一起交付。

准确状态是：

> ch05 是当前实施目标；ch06 配置已进入两步设计形态，但 ch06 生产实现尚未完成，当前属于待确认后再单独实施的准备状态。

## 3. P0：后端缺少 ch06 专属输出规范化与校验

### 3.1 已核验事实

当前 platform/backend/app/routers/steps.py 有 _is_ch05_step、_normalize_ch05_run_output、_validate_ch05_output，未发现对应的 ch06 专属逻辑。

通用 _validate_parsed_against_types 只记录 warning，不阻止错误结构进入 saved 或 submitted。当前没有后端硬校验：

- step-1 likes 为对象数组并含 text、locked；
- step-1 不带 step-2 的 aspects、linked_strengths；
- step-2 likes 为嵌套对象数组；
- aspects、linked_strengths 子项为对象数组且含 text；
- sources 为来源数组；
- locked 为 boolean；
- commentary 为非空只读字符串；
- locked 项重新生成时原位保留。

### 3.2 结论

这是实现缺口，不是设计冲突。请设计侧确认无需改变设计，开发按上述现有契约补齐即可。

建议开发实现：

1. 增加 _is_ch06_step；
2. step-1/step-2 分别 normalize + validate；
3. 后端控制 locked、source/sources 的可写边界；
4. 兼容旧 LLM 字符串列表，但持久化只保存 canonical 结构；
5. 对 /run、/output、/submit 三条路径校验；
6. 增加 ch06 专项契约测试。
