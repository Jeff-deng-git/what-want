## 4. 开发侧问题 4：summary 是否属于 stale 隔离范围

> ⚠️ **勘误（第六轮修正）**：本节原结论方向（summary 不为 ch06 stale likes 增加门禁）仍成立，但下方支撑论据有误——第五轮复核时 grep 了不存在的 `app/routers/summary.py` 路径，误判「summary 不引用 load_profile」。经第六轮按 `agent.py:138` + `assembler.py:385-389` 实测更正如下。

**结论：summary 不为 ch06 stale `likes` 增加门禁（保持现有行为即可）。**

- 实测 `app/runtime/agent.py:138` 的 `run_summary()` **调用 `load_profile(user_id)`**，`agent.py:139` 将 profile 传给 `build_summary_prompt()`；`app/runtime/assembler.py:385-389` 的 `build_summary_prompt()` 仅读取 `profile.values` 或 `profile.work_purpose` 作为章节摘要额外角度，**不读取 `likes`、`talents` 或任何 ch06 step-2 输出**。
- 因此 summary 通过 `load_profile()` 读取 learner_profile，但以 `values`/`work_purpose` 为角度、不碰 ch06 `likes`；summary **不属于 ch06 stale likes 的消费方**，无需为其增加 stale 门禁。
- summary 的「历史查看」仅针对章节摘要缓存，不展示 stale 的 ch06 step-2 结果。后续若需让 summary 消费 `likes`（如个性化摘要），须另开设计变更，不纳入本次 ch06 实施。
