# 全书重构设计总览（What Want 平台）

> 文件：`docs/全书重构设计总览.md`
> 版本：v1.0 ｜ 状态：设计定稿，待工程边界确认
> 定位：ch1–ch8 全部 PRD 与配置的**伞文档**。站在「全书统一重构」而非「第四章改写」的视角，把 mentor（全书常驻苏格拉底导师）+ summary（全书常驻摘要 Agent）+ 8 章配置 + 统一 Agent 运行时 当成一套系统设计。

---

## 0. 一句话结论

平台不是「8 个独立章节 + 2 个写死的 LLM 调用」，而是一套**以用户认知进展为主线的统一系统**：

```
用户自评产出（8 章 exercises）
   ↓ 落库 + compaction
learner_profile（跨章压缩档案）
   ↓ 上下文装配器（compact + select，≤3k token 护栏）
统一 Agent 运行时（step / mentor / summary 三种模式，配置驱动）
```

刘老师（mentor）与章节摘要（summary）不是某章的功能，而是**贯穿全书的常驻能力**，和 8 章练习共享同一份 `learner_profile`。

---

## 1. 全书能力地图（三种 LLM 调用，同走统一运行时）

| 能力 | 触发 | 配置源 | 输入 | 输出落点 |
|------|------|--------|------|---------|
| **step（练习点评）** | 用户提交某章练习 | `chapter_config_chNN.json` 的 `exercises[].llm_role=assist` | 用户答案 + 本章 MD | 该章 `output_fields`（→ learner_profile） |
| **mentor（刘老师对话）** | 用户点「问刘老师」（opt-in） | `mentor_config.json` + 本章 `mentor_hooks` | learner_profile + 钩子 + 本章 MD + 近期历史 | 对话（不落库，仅历史） |
| **summary（章节摘要）** | 进入章节 / 手动 regenerate | `summary_config.json` | 本章 MD（前 12000 字） | 摘要 tab |

**关键约束**（详见 `mentor_design_spec.md` §5）：
- 三种调用**统一**经 `app/runtime/assembler.py` 装配，杜绝现有 `chat.py` / `summary.py` 各自硬编码 `md[:12000]` + 固定人设。
- 每轮 prompt 受 **≤3k token 护栏**：人设 400 + 档案 600 + 钩子 400 + 历史 800 + 用户 200；超载先截历史，再退化「仅档案+钩子」，**绝不全量注入八章原始数据**。

## 2. learner_profile：全书跨章连续性的主干

`learner_profile` 是贯穿 8 章的压缩档案（DB 表 `learner_profiles`，按 user_id 存，≤800 token）。八章产出按如下映射汇入：

| 字段 | 来源章节 | 章节练习产出 | 被谁消费 |
|------|---------|------------|---------|
| `misconceptions_cleared` | ch1 | 误区自检 | ch2 刘老师（解释内外标准）、全书 |
| `external_voices` | ch1 | 外部声音 | ch2 刘老师（连接内外标准） |
| `internal_external_ratio` | ch2 | 内外占比 | ch4 刘老师（工作目的参照） |
| `reclaim_item` | ch2 | 收回主动权事项 | ch4 刘老师（工作目的参照） |
| `likes` | ch3（种子）/ ch6（权威） | 喜欢的事 | ch7 组合（**只读 ch6 权威 `likes`=`profile.likes`，即 ch06 step-2 成功提交的结构化版本，不读 ch3**）、ch8 实践 |
| `talents` | ch3（种子）/ ch5（权威，含◎〇△评级） | 擅长的事（才能） | ch7 组合（读 ch5 talents）、ch8 实践 |
| `importance` | ch3 / ch4 | 重要的事（价值观） | ch4 深化、ch8（如适用）；**ch7 不消费 importance**（ch07 `references` 不含 importance） |
| `work_purpose` | ch4 | 工作目的 | ch5/ch6/ch7/ch8 刘老师 |
| `values` / `ranked` | ch4 | 价值观排序 | ch8 成功宣言 |
| `intersection` | ch3 | 三圆交集 | ch8 实践（如适用）；**ch7 不消费 intersection**（ch07 `references` 不含 intersection，ch7 组合的是 ch4–ch6 深化版 `ideal_works`） |
| `success_statement` | ch8 | 成功宣言 | （终点，可回写人生目的） |

> **设计要点（2026-08-13 校正）**：ch3 是三要素**框架/种子章**（早期扁平 likes/talents/importance）；ch4–ch6 各自**深化**为权威版本——ch4 `values`/`work_purpose`、ch5 `talents`（含◎〇△）、ch6 `likes`（结构化：领域/方面/关联擅长）。**ch7 组合的是深化版**（ch6 `likes` × ch5 `talents`，用 ch4 `work_purpose` 筛分、以 `values` 作核心价值观），其 `step_context`/`mentor_hooks.references=[talents,likes,work_purpose,values]`，**不读 ch3、不消费 importance**。因此 ch3 的 seed 与 compaction 映射仍是重构优先项，但 ch7 上游门禁须锁定 ch4/ch5/ch6 而非 ch3。

## 3. 重构前后对比

| 维度 | 现状（重构前） | 目标（重构后） |
|------|--------------|--------------|
| 练习点评 | `step_runner.py` 读 DB（配置驱动）✅ | 不变，沿用 `chapter_config` |
| 刘老师对话 | `chat.py` 硬编码「刘老师」system + `md[:12000]` + `HISTORY_LIMIT=10`，无 profile/hooks | 走 `app/runtime/agent.py:run_mentor`，读 learner_profile + mentor_hooks + 滑动历史 |
| 章节摘要 | `summary.py` 硬编码「资深图书编辑」`SUMMARY_SYSTEM` + `md[:12000]` | 走 `app/runtime/agent.py:run_summary`，读 `summary_config.json` |
| 配置位置 | 运行时配置在 DB（`llm_roles`/`chapter_configs`），json 仅作 seed 源 | 不变；新增 `mentor_config.json` / `summary_config.json` 作为 seed 源 |
| 跨章连续性 | 无（各章孤立） | learner_profile + compaction 任务 |
| 上下文装配 | 无（拼接） | `assembler.py` compact + select + ≤3k 护栏 |

> **已落地**：`app/runtime/` 四个文件（`__init__.py` / `config_loader.py` / `assembler.py` / `agent.py`）语法校验通过，但**未接入任何路由**，现有 chat/summary/step_runner 继续原样运行（灰度切换待工程边界确认）。

## 4. 统一运行时骨架落点

`platform/backend/app/runtime/`（代码草稿，不破坏现有运行）：

- `config_loader.py`：读 DB（`llm_roles` / `chapter_configs` / `learner_profiles`），json 仅作 seed 源。
- `assembler.py`：compact + select 装配；导师必注入 profile、摘要可选增强；含 ≤3k token 护栏。
- `agent.py`：`run_step` / `run_mentor` / `run_summary` 三模式 dispatcher，取代 chat/summary 内联 `call_llm`。

## 6. 工程接入里程碑与边界（待用户整体计划确认）

重构按依赖顺序分四步，**不与用户「全部重构」大计划冲突**：

1. **数据层**：新建 `learner_profiles` 表 + `conversation_summaries` 表；实现 compaction 任务（step 提交或计数触发廉价 LLM 压缩）。← 地基，优先。
2. **配置层**：seed 增加 `mentor` / `summary` 两条 `llm_roles`；把 `mentor_config.json` / `summary_config.json` 灌入 DB。
3. **运行时接入**：灰度将 `chat.py` / `summary.py` 切到 `app/runtime/agent.py`（保留旧路由可回滚）。
4. **前端**：`renderStepOutput` 补 `groups` / `conversions` 渲染分支（ch4 必须）；补章末桥接卡（形态 B，opt-in）。

> ⚠️ **边界待确认**：若用户「全部重构」涵盖前端框架/DB 大改，则本运行时骨架作为「核心底座」先冻结，待整体方案定后再迁移 chat/summary/step；避免孤立接入后被推翻重来。
